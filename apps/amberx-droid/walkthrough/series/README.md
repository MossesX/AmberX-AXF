# AmberX in three minutes (demo video series)

Seven short browser walkthroughs, one topic each, recorded on live data. Build
`demo-video-series-three-minute-browser`. The scripts are in `scripts.mjs`. Each scene has `say` (the narration and
captions), `shot` (what the camera shows) and `staged` (marks a screen that isn't built yet; it is shown as a mock with a
visible Preview label). They reuse the 2-hour walkthrough pipeline in `../` (recorder, Piper TTS, assembler, player).

| # | id | Title | App | Skin | Staged scenes |
|---|---|---|---|---|---|
| 1 | voice-control | Talk to it: voice control in AmberX | amberx-droid (phone) | control-room | none |
| 2 | orchestrator-agents | How the orchestrator builds everything with agents | console-web | newsroom | none |
| 3 | plan-studio | Plan Studio: plan by talking, build with one tap | console-web | ledger | none |
| 4 | skins-tokens | Skins and hot-swappable tokens | console-web | atelier | none |
| 5 | ui-designer | The UI designer: screens from building blocks | console-web | clinic | the screen canvas (7) |
| 6 | axhub | axHub: your server, your approvals, your apps | axhub-web | windows | none |
| 7 | build-an-app | Building an app, start to finish | console-web + phone | atelier | library matrix, canvas, action API, install (4) |

The hero stories and deep dives (steps s5 onward, most with a 60-second cut) live in `more/`, one file per video; see
`more/README.md` for the extra fields (`kind`, `camera`, `short`, `facts`).

Check the scripts (shape, ids, skins, apps, running time 2:30 to 3:20 at 150 words a minute, and that any video with
staged scenes says "preview" out loud):

```bash
node apps/amberx-droid/walkthrough/series/check.mjs --table
```

## The staged designer mock (s2)

The full UI designer isn't shipped, so every staged scene that shows it (the UI designer video, the build-an-app video,
the library matrix and assembly view of the hero stories) is recorded on one mock page, `../designer-mock.html`,
generated by `mock/build.mjs`. A **Preview · not shipped yet** label never leaves the screen. The page is real where it can
be:

| What | Where it comes from |
|---|---|
| Every colour, size, gap, font, radius and border | the `--fx-*` token set of each of the six skins, compiled through the real engines (`mock/tokens.mts`: colour theme, style theme, surfaces, scrollbar, typography / density / sizing, layout, and the button, container, toolbar and tab-group styles the skin picks) into `mock/tokens.json` |
| The controls | `framework/ui/axf.css` inlined: toolbars (`role="toolbar"` + label), tabs, cards, tables, fields, chips, buttons, status bar |
| The parts palette | the asset type registry, `framework/schemas/asset-types.json`, grouped as it is there |
| The library matrix columns | `framework/catalog/libraries.json` (ids, modules, names) |
| The layout picker | `framework/assets/layout` |
| The time tracker's entries and week | sample rows, labelled **Sample data** on screen |

Scenes (`mock: '<id>'` on a staged scene; `check.mjs` refuses an unknown one): `canvas` (pick a layout, drop a toolbar,
grid, tabs, form), `grid` (sort; the toolbar's screen-reader label), `phone` (desktop + phone frame), `skin` (the picker,
each step switches skin and re-renders), `voice` (a spoken request arrives as a console-control call; a search bar lands),
`assets` (the approved screen saved as an asset), `app` (the time tracker's Today and Week screens assembled part by
part), `actions` (every action with its REST, MCP, CLI and voice entry), `matrix` (features × real libraries, ticks fill
in; `rows=` names the features).

```bash
node apps/amberx-droid/walkthrough/series/mock/build.mjs            # regenerate designer-mock.html
node apps/amberx-droid/walkthrough/series/mock/build.mjs --tokens   # recompile the skins' tokens first (npx tsx)
node apps/amberx-droid/walkthrough/series/mock/build.mjs --list     # scenes, steps, params, skins
node apps/amberx-droid/walkthrough/series/mock/shot.mjs matrix --skin ledger --step 3   # a screenshot (--all: every scene)
```

Driving it: in the recorder, `h.mock('matrix', { skin: 'atelier', rows: ['Receipts', 'Budgets'] })`, `h.step()`,
`h.skin('ledger')` (record.mjs serves the page at `https://walkthrough.local/mock`). In a browser,
`designer-mock.html#matrix?skin=atelier&rows=Receipts,Budgets`, and `window.wtMock` (`scene`, `step`, `skin`, `state`,
`scenes`, `skins`) does the same; `window.wtStep()` is the recorder's step hook. The mock is a recording prop, not a
console screen: it has no console-control address and ships with nothing.

What the next steps do with this:

- s3 turns each `shot` into an `act` with the recorder helpers (`mock`, `step`, `skin` for staged scenes) and records each video separately.
- s4 adds narration, sync, the themed player (each video's `skin`), MP4 export and publishing.
