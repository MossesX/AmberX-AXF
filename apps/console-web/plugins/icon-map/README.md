# Icon map (console plugin)

Every icon, badge and logo slot in every app, plugin and screen, in one map (icon-map@1,
`framework/core/engines/icon-map-rules.mjs`), with the icon pack in force and per-slot picks. Brett (Nov 13 2026):
"a map of every single icon and badge for the whole entire app, every plugin, every screen, every UI; a template so I
can change every single one with a click".

## Reach it

| How | Where |
| --- | --- |
| Screen | View → Icon map · nav `icon-map` · deep link `console_show view:icon-map` / `console_open icon-map` |
| REST | `/api/plugins/icon-map/{map,tree,roles,glyphs,packs,state,slot/{id},resolve,check}` (GET), `PUT /pack {pack}`, `DELETE /pack`, `PUT /slot/{id} {glyph}`, `DELETE /slot/{id}`; the same under `/api/control/icon-map/<command>` (plugin-commands@1) |
| MCP | `icon-map_map`, `icon-map_packs`, `icon-map_state`, `icon-map_pack-set`, `icon-map_pack-clear`, `icon-map_slot-set`, `icon-map_slot-clear`, `icon-map_resolve`, `icon-map_check`, … (`plugin_commands icon-map` lists them) |
| CLI | `axf icon-map pack-set --pack duotone`, `axf icon-map map --q save`, `node framework/cli/icon-map.mjs …` (the map from the files, no console needed) |
| Voice | "switch to the duotone icon pack", "use the filled icon pack", "back to the default icon pack", "open the icon map" |
| Console actions | `icon-map.open`, `icon-map.pack.use:<pack>`, `icon-map.pack.clear`, `icon-map.slot.set:<slot>:<glyph>`, `icon-map.slot.clear:<slot>`, `icon-map.slot.open:<slot>`, `icon-map.refresh` (search, context menu, `function:` control targets) |
| Other UI tools | web service `axf.icon-map@1` (`globalThis.__axfWebServices`): `open(slot)`, `resolve(name, slot?, role?)`, `setSlot(slot, glyph \| null)`, `usePack(pack)`, `packs()`, `map(query)` |

## The page

Two views (TabGroup): **Tree** (app → plugin / screen owner → surface → slot, with counts; a search opens the
branches it matches) and **List**. Filters: search, app, surface, kind (icon / badge / logo). Every row previews what
the place draws now, through the runtime, so a pack switch or a pick shows at once. **Change** opens the slot panel:
previews at three sizes, why it draws what it draws (pick, pack role, pack glyph, framework, fallback) and a glyph
grid; one click on a glyph changes that place.

## The template

One icon-pack@1 file maps every role in the map (168 today: the framework vocabulary, every glyph as a role of its
own name, and each plugin's declared roles) to a glyph, plus the glyph art. Change a role's line to change every place
of that role; apply the pack to change every icon at once. Get it with **Download template** on the page,
`GET /api/plugins/icon-map/template?from=<pack>`, MCP `icon-map_template`, `node framework/cli/icon-map.mjs template
--from <pack> --out my-pack.json`, or by voice ("download the icon pack template").

## Restore

Each slot and the pack keep their edit history (`prev` on every history row). **Restore previous edit** goes back one
edit; a restore counts as an edit, so pressing it again goes forward. **Restore from axHub** uses the icons axHub's
look document held when the console last loaded the look (the open console sends that copy to `PUT /hub-copy`; with
axHub sync off there is none and the route answers 503 with the steps). REST `POST /slot/{id}/restore {from}`,
`POST /pack/restore {from}`; actions `icon-map.slot.restore:<slot>:previous|hub`, `icon-map.pack.restore:previous|hub`;
voice "restore the previous icon pack", "restore the icons from axhub".

## Packs

41 icon-pack@1 assets in `framework/assets/icon-pack/` (shared: every app ships them). Each declares `themable`
(true: currentColor, follows the skin's colour and stroke; false: fixed-colour art) and its licence.

| --- | --- | --- | --- |
| Lucide | lucide | yes | ISC |
| Tabler | tabler-outline, tabler-filled | yes | MIT |
| Feather | feather | yes | MIT |
| Iconoir | iconoir-regular | yes | MIT |
| Heroicons | heroicons-outline | yes | MIT |
| Phosphor | phosphor-regular, -thin, -light, -bold, -fill, -duotone | yes | MIT |
| Bootstrap Icons | bootstrap, bootstrap-fill | yes | MIT |

| Octicons, Ionicons (glyph) | octicons, ionicons-filled, ionicons-sharp | yes | MIT |

| Badge styles | badges-dot, -ring, -square, -shield, -hex, -diamond; badges-traffic | yes; traffic no | MIT (AXF) |
| Logo marks | logo-orbit, -hex-spark, -monogram, -bolt, -ring; logo-amber-gem | yes; gem no | MIT (AXF) |

| Earlier | amberx-outline, pack-021, pack-053 | yes | AXF |

The imported packs are generated by `node framework/cli/icon-packs-import.mjs <unpacked npm tarballs dir>` (SVG read as
data, shapes to path commands, scaled onto the grid; a glyph a set lacks or can't draw faithfully, e.g. even-odd fills,
falls back to the framework glyph). Fixed-colour packs carry `layers: [{ d, color }]` per glyph with a one-colour `d`
fallback; until the icon-pack@1 colour-layer step (Fable) lands they draw that one-colour fallback.

## State

`icons.json` in the plugin's data folder (`.axf-console/plugins/icon-map/`, or `AXF_ICON_MAP_DIR`):
`{ "pack": "<icon-pack id or ''>", "slots": { "<slot id>": "<glyph>" }, "history": [...], "hub": { "pack", "slots", "at" } }`. The open console reads it on load and
every few seconds, and writes it back when a pick is made on screen, so REST, MCP, CLI, voice and the page agree.
The runtime keys are `axf.icons.pack.app` (the skin engine's own key) and `axf.icons.slot.<slot id>`.
