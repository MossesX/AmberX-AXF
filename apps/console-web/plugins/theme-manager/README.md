# Theme manager (console plugin)

`ai.amberx.axf.console.theme-manager` · built on Opus.

Roll colour / style / layout themes, or everything themeable, and choose exactly which tokens a roll may change.

- **Tree** of every token, built from `framework/schemas/asset-types.json` + the registered assets (new asset types appear by themselves): tri-state ticks, locks (never rolled), filter, presets (all / none / colors only / accents only / invert + your own named presets, saved server-side), "only" this branch. On a phone it drills down one level at a time.
- **Sane rolls** (`web/rollEngine.ts`): colour themes get a harmonious palette with contrast-checked text and status colours; numbers stay inside the range the known themes use; enums pick known values. Readability warnings for the active colour theme.
- **Live preview** through the engines (`registry.register` + `rt.swap` on `tm-preview-<type>-a|b`), undo/redo (50 steps), pin favourites, edit any value by hand, back to the saved look.
- **Save as asset**: one standard asset@1 per changed type (name, tags), kept in `.axf-console/plugins/theme-manager/themes/<type>/<id>.json`, registered on start; the ones you applied last come back on reload. Apply, rename, duplicate, export, import, delete. Built-in ids are refused, so built-ins are never changed.

- **Appearance and skins:** this plugin's page and Settings → Appearance are one shared panel (`AppearancePanel`, framework/libs/settings): Skin (picker with live preview, Apply, Reset) and the Use skin switch (off by default, this app only), Style / Colour / Layout theme, Visible parts, Navigation menu, Restore to default with one undo. With a skin on, a pick overrides that part only (a dot and Back to skin), except the colour theme: a skin owns everything and carries its colour theme as one switchable section, so picking a colour theme switches it inside the current skin (same skin, no dot, no new or forked skin; "Skin's colours" goes back to the skin's own). Right-click any chrome for Restore to default too. Design packages show as skins. The format is skin@1 + app-look@1 (`framework/core/engines/skin.ts`, `framework/spec/APPEARANCE-SOURCE.md`). **Every asset type and every scope (build skins-asset-types, Nov 7 2026):** the panel also shows *Where the skin applies* (hub-wide → this app → a screen → a plugin, the nearer level wins; Follow the hub-wide skin switch; per-screen / per-plugin Inherit / Skin / Off) in three switchable layouts (rows, dialog, matrix) and *What a skin covers* (every registered asset type, grouped by how a skin reaches it: slot / parts / reference / bundle / none; skin-coverage@1, `framework/core/engines/skin-coverage.mjs`).

Routes (console token, 404 when disabled): `GET/POST /themes`, `PUT/DELETE /themes/{type}/{id}`, `GET/PUT /presets`, `GET /skins`, `POST /skins/{app}/use` (`{skin, scope?}`), `/off` (`{scope?}`), `/inherit` (`{scope}`), `/follow` (`{on}`), `/back` (`{slot}`), `GET/POST /skins/{app}/color` (`{theme, scope?}`: the colour theme inside the skin in force; `default` = the skin's own; the skin stays and no skin is made), `/restore`, `/undo`, `GET /skins/{app}/at?scope=`, `GET/POST /skins/global` (`{skin}` | `off`), `POST /skins/global/color` (`{theme}`), `GET /skins/coverage`, `GET /skins/covers/{skin}` (scope = `ui:<id>` | `plugin:<id>`). They become MCP tools by themselves (plugin-commands@1); the CLI is `node framework/cli/skins.mjs`. Voice: "use the Windows skin in the console" and "restore AmberX to default" go through these tools; inside an app, the actions `skin.use:<id>`, `skin.off`, `skin.restore`, `skin.undo`, `skin.inherit:on|off` and `skin.scope:<ui|plugin>:<id>:<on|off|inherit>[:<skin>]`.
Self-test: `python3 apps/console-web/plugins/theme-manager/test.py`.
