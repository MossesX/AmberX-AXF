# Porting AmberX AXF to another stack

AXF is one framework with several **ports** (Android/Kotlin, React/Next/TypeScript/Node, Python/PyQt6, …).
A port is quick to write because almost everything is already shared and language-neutral:

| Shared by every port | Where |
| --- | --- |
| Asset format (`asset@1`) and every starter asset | `framework/assets/**`, `framework/schemas/asset-types.json` (+ per-port extension specs such as `asset-types.android.json`) |
| Manifest / lock / plugin formats | `framework/schemas/*.json`, `app-structure.json`, `plugin.schema.json` |
| Engine behaviour (theme, layout, component style, UAC, context menu, actions, validation) | `framework/spec/fixtures/*.json` — golden outputs generated from the reference TypeScript engines |
| Standard vocabularies | action ids (`StandardActions`), UAC permission ids, extension-point ids, route/settings/work/session/plugin contracts (`framework/android/axf-kernel/.../contract`, mirrored in `framework/core/types.ts`) |
| Plugin inventory (`plugin-inventory@1`: dependencies, dependents, health, clashes, graph) | `framework/core/engines/plugins.ts` = `axf-kernel/.../plugins/PluginInventoryEngine.kt` = the console plugin's `server/engine.py`; fixture `spec/fixtures/plugin-inventory.json` |
| Application menu (`app-menu` asset + run-time contributions + live lists → one compiled tree; placement, UAC gating, badges, check marks, depth cap, conflicts) | `framework/core/engines/appmenu.ts`; fixture `spec/fixtures/app-menu.json` (web checker `spec/check-app-menu.mts`). **Android twin deferred** (`AppMenuEngine.kt`, `AxfRuntime.addAppMenuItems` / `registerAppMenuProvider`, Compose menubar): Android port on hold, Brett Oct 21 2026. The Kotlin validator is spec-driven and accepts the new optional item fields as they are. |
| Page frame order (React `AppShell`): banner asset → `app.frame.head` slot (app tabs above the menu, Oct 22 2026) → application menu bar (moved out of the layout grid above the live banners, Oct 22 2026; its `auto` grid row stays empty) → `app.frame.banners` slot (library banners, above any page-top bar; `FrameBanners`) → `app.frame.top` → layout → `app.frame.cover` | `framework/react/AppShell.tsx`, `framework/react/components/Slots.tsx` (Oct 21 2026). **Android twin deferred**: Compose `AppShell` banner above any page-top slot, plus an `app.frame.banners` slot: Android port on hold, Brett Oct 21 2026. |
| embed@1 takes + page mode + host/guest messages (a host takes `settings` / `notifications` from the apps it embeds; guests drop those hooks and ask the host; `page=settings` = the page alone) | `framework/core/engines/embed.ts` (second half), runtime `hostTakes` / `takenByHost` / `postToHost`, app-menu env `taken`, React chrome filters + `AppShell` page mode + `keep`; fixture `spec/fixtures/embed-takes.json` (Oct 21 2026). **Kotlin host side built** (`EmbedTakes`, `EmbedTakesConformanceTest`, lib-hub `WebAppHolder(takes)` + `AxfEmbedHost` bridge + `send`) because Patches needs it. **Guest side deferred**: `AxfRuntime` takes / page mode for a native Android app shown inside another (none exists yet): Android port on hold, Brett Oct 21 2026. |
| embed@1 plugins a host makes unneeded (`skipWhen`: `embedded` / `take:<fn>` / `hidden:<type>`; page mode never skips) | `framework/core/engines/embed.ts` `embedSkipReason`, `AxfWebLibrary.embed.skipWhen`, `installLibraries` skips + `rt.skippedLibraries` / `noteSkippedLibraries` launch log, Settings → Plugins lists them; checks in `spec/check-embed.mts` (Oct 22 2026). **Android twin deferred** (kernel module loader skipping modules inside a host): no native Android app runs inside another yet; Android port on hold, Brett Oct 21 2026. |
| Embed (`embed@1`: a host app's marker on embedded pages → the chrome the embedded app hides; hide engine `forced` layer) | `framework/core/engines/embed.ts` = `axf-kernel/.../engine/EmbedEngine.kt`; fixture `spec/fixtures/embed.json` (`spec/check-embed.mts`, `EmbedConformanceTest`) + `forced` cases in `hide.json`. Host side on Android: `lib-hub` `WebAppView` / `WebAppHolder` (Patches); web host (frames) not built |
| axHub connector, first slice (hub address rules, hub URLs, approvals feed + status mapping, seen ids) | `framework/libs/hub/hub.ts` = `framework/android/lib-hub/.../HubRules.kt`; fixture `spec/fixtures/hub-approvals.json` |
| Work (`work@1`: poll-job specs with interval bounds, per-outcome back-off, one-time notices, run conditions; the job state machine whose effects a host carries out) | `framework/core/engines/work.ts` = `axf-kernel/.../work/WorkEngine.kt`; fixture `spec/fixtures/work.json` (`spec/check-work.mts`, `WorkConformanceTest`); Android host `framework/android/lib-work` |
| Interop contracts (protocol-neutral) | `framework/spec/INTEROP.md` — action/event descriptors, exposure, call origins, `surface@1`, wire error codes, protocol adapters (`axf-kernel/.../interop`; **not yet mirrored in `framework/core`**) |
| Build engine | `framework/cli/*.mjs` — `init`, `validate`, `new-asset`, `new-module`, `new-demo`, `dev`; a port adds a template folder with a `template.json` |
| Feature catalog + tracker | `framework/catalog/*.json`, `tracker.json` — the console shows every port's status from the same data; typed models + parsers for catalog@1, status, tracker@1, library@1, libraries@1, boilerplate@1, boilerplates@1 in `core/catalog.ts` = Kotlin `ai.amberx.axf.kernel.catalog` (fixture `spec/fixtures/catalog.json`) |

## What a new port implements

1. **Kernel core** (pure, UI-free): envelope parse, open type registry, validator, registry, the six engines, runtime state + hot-swap, action bus, module/extension registry, event bus, flags, config, migrations. Port the Kotlin kernel or the TypeScript `framework/core` — they are the same design, file for file.
2. **Platform seams**: clock, ids, dispatchers/threads, key-value store, secure store, logger, telemetry, permissions, file layout, work scheduler, session provider, plugin loader. (`platform/Platform.kt`, `contract/*.kt`.)
3. **UI layer** that reads only the compiled tokens: theme → native theme, `CompiledLayout` → native layout regions, `ComponentStyles` → native widgets with every variant, menus/toolbars/nav/context menus/dialogs/toasts from the typed assets. The web port's `framework/ui/axf.css` + `framework/react` and the Android `axf-ui` are the two references. Every port ships the shared form controls with the same names and behaviour (Switch, Field, TextField, SelectField, ChoiceGrid, Note, Section, Markdown, LibraryParamField — see `THEMING.md` → Shared form controls); `LibraryParamField` reads the library@1 parameter rules (`core/library.ts` = Kotlin `kernel.library.LibraryParams`, fixture `spec/fixtures/library-params.json`).
4. **App template** for `axf init --template <port>` (a `template.json` + boilerplate), and a bootstrap (the port's equivalent of `AxfApplication` + `AxfRoot` + `AppShell`).
5. **Interop gate**: `AxfInterop` (descriptors, exposure + grant + role checks, schema check, audit) and the adapter extension point, with the same wire error codes — see `INTEROP.md`.
6. **Conformance test** that loads `framework/assets` and asserts the fixture outputs (see `ConformanceTest.kt` for the Kotlin version).

Regenerate fixtures after changing a reference engine: `npx -y tsx framework/spec/gen-fixtures.mts`.
