These are shared files (axhub-projects@1). This folder syncs with `/projects/_shared/_claude/` on the hub and with

## Before building anything
- **Fix it yourself (Oct 30 2026, Brett: "Why do I have to tell you to fix something when you have the tools to do it?"):** when anything is broken (a dead or expired key, a stuck or crashed build, a failed launch, CI red, a container restarting, missing config) and the tools at hand can fix it, fix it straight away as a veto call (axHub, with a plain `reason`), then tell Brett what was fixed. Never ask him whether to fix it. Ask only when the fix truly needs his hands (making a new token on github.com, paying, a physical device) or a real choice between options; then it goes in a banner item with the exact steps. In AmberX-AXF the console does the same by itself: health@1 checks carry an auto-fix that runs before an item turns red (systems check → Settings → Fix it yourself: on / ask first / off per check). <!-- axf-plugin:systems-check -->
- **Models: the build orchestrator decides, per step (Oct 27 2026, Brett: "Forget previous model select rules"; replaces "Pick the model first" and "Ask every time").** Every build is broken into steps of 30 min or less in the Build orchestrator (`_claude/builds/orchestrator.json`, console → Builds → Build orchestrator, `apps/console-web/plugins/build-orchestrator/orchestrator.mjs`), each step pinned to **Fable** (cross-port contracts, kernel/engine internals, schema + migration design, heavy refactors, work that changes how GUIs work across apps) or **Opus** (everything else). Don't ask for a model per build. **Ask for approval (card) only at a model switch** between phases, then `orchestrator.mjs act approve <id> <phase>`. Save tokens: one session, no new session or sub-agent unless a step needs it, briefs carry only the current phase. You can't switch models yourself: at a switch, stop and give Brett the next phase's brief (`orchestrator.mjs brief <id>`) to run on that model. <!-- axf-plugin:build-orchestrator -->
- **Check the pending build list** before building. Builds parked until their model is available are listed in AmberX-AXF (`node framework/cli/pending.mjs`, MCP `pending_list`, console → Pending builds) and on the claude.ai Pending Builds page (https://claude.ai/artifact/HTwGSP7HcEt5yBd3MNz2Ye, db collection `builds`). "Add it to the pending list" means park it, don't build it.
- **"Put it in a plan for later" = a Plan Studio plan, not a build (Oct 30 2026, Brett):** when Brett says to put something in a plan for later (or "plan it", "save it as a plan"), it becomes a **parked** plan in Plan Studio (plan@1, console → Builds → Plan Studio; CLI `node apps/console-web/plugins/plan-studio/plans.mjs add "<title>" --status parked --category "A > B"`; claude.ai: `axhub.memory_write` project `amberx-axf`, area `data`, path `plan-studio/plans/<id>.json`; server parts: capability `plans@1` `park()`), never an orchestrator build or a pending item. It only becomes a build when Brett says so (Plan Studio → Turn into a build). <!-- axf-plugin:plan-studio -->

If an item would clash but shouldn't be built now, say so and add a note on that item. When adding to the queue, merge into an overlapping item instead of adding a duplicate.

## Projects
- **Every project has a manifest**, `project.manifest.json` (`project-manifest@1`, schema and rules in AmberX-AXF; rules are managed in the Dev Console → Standards). It names the project, its repo (even one that doesn't exist yet, for future naming) and its shared data. Its `name` is the project's folder on the hub, `/projects/<name>/`.
- **No project is loaded or compiled without a valid manifest.** The AXF build engine, the Dev Console and every template refuse to work on a project whose manifest fails validation.
- Every project has `_claude/` (memory/, instructions/, rules/, shared/) synced with `/projects/<name>/_claude/`, and its manifest's `data.shared` files synced with `/projects/<name>/_data/<same path>`.
