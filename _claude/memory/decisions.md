# Decisions (AmberX AXF)

## Framework

- Named **AmberX AXF** (originally "Frame", from his spec doc `docs/Frame.md`). Cross-platform: Android (Kotlin/Compose), React/Next/TypeScript/Node, Python/PyQt6 later; quick porting between stacks and seamless switching between third-party UI libraries.
- **Everything visible is a hot-swappable asset** (`asset@1`): themes, layouts, menus, toolbars, nav, dialogs, buttons, sliders, containers, UAC policy… All left at defaults, every app looks identical.
- **The framework is built on the fly by the apps that use it**: each app breaks out libraries, modules, packages and assets into the framework. The first app on a port sets conventions but contributes only one template; its hard constraint is engine compatibility for porting.
- Oct 2026: the Android port is built alongside the first Android app, which defines the kernel, engines, templates, assets and placeholders for future ports.
- Oct 18 2026: layout regions have a typed slot contract (`asset-types.json` → `layout.slots`); toolbar, nav-menu and app-menu are styled by the component style engine.
- Oct 18 2026: every UI build (session, terminal, MCP, API) takes `--` switches for options; `--wrap-groups` makes every section/group collapsible with a small top-right icon. Future builds default it off; existing files set on.
- Oct 18 2026: live framework data is read from the server hub (now `/projects/amberx-axf/_data/`, see below).
- Planned next big rule (pending, Fable): **every UI element is a named asset** (element vs parent assets, namespaced ids, instance vs skin, slot rebinding).
- Oct 18 2026 (built on Opus): **randomize rolls have include rules.** A roll ("Randomize all") changes only slots switched into rolls and picks only assets switched into rolls. Context menus are out by default twice over: the context-menu slot is off, and every context-menu asset has `roll: false` by default (each must be switched in one by one). Switches live in Settings → Appearance → Randomize / Assets in rolls, in code (`setRollSlot`, `setRollAsset`) and as actions (`roll.slot:<type>:on|off|default`, `roll.asset:<type>:<id>:on|off|default`). uac-policy is never rolled.
- Oct 18 2026 (built on Opus): the console's default toolbar is the new **Console Search** toolbar asset: a live search box (dropdown on every keystroke) over pages, actions, settings, dialogs, assets, open windows and words on pages; picking a result brings it onto the screen. Any toolbar asset can turn it on with `data.search.live`.
- axHub's control interface is a Dev Console **plugin** (not a hardwired tab); approving pending calls needs a PIN only Brett knows.
- Oct 18 2026 (built on Opus): every project built with or for AmberX has a manifest (`project.manifest.json`, project-manifest@1) defining its identity and repo (a repo that doesn't exist yet is still defined, for future naming); its `name` names the project's folder in the hub's `/projects`. Every template ships one, `axf init` fills it in, and the build engine refuses to load or compile a project whose manifest fails validation. The rules live in the Dev Console's new **Standards** section. Each hub project folder has `_data/` (the manifest's `data.shared`, laid out like the project) and `_claude/` (memory, instructions, rules, shared); projects have the same `_claude/`. axHub decisions #70-#76.
- Oct 18 2026 (built on Opus): **claude-project**: one command (shell, `axf claude-project`, `/claude-project` in any session) makes any folder a Claude project and gives it a home on GitHub (with Claude app access, so Claude.ai sees it), the VPS (git remote + working folder) or the device. Any folder Brett points it at gets a manifest, even if it isn't an AXF project. For apps not built on AXF it asks **each time** whether to port by baking AXF in or rebuilding from a boilerplate; ports are parked for Fable (`app-port-engine`, `port-<name>`).
- Oct 18 2026: xGallery's New project wizard stays in xGallery and becomes an AXF library later so any AXF app can clone its install **with current data** (pending `lib-clone`, Fable).
- Oct 18 2026 (built on Opus): the project-creation side of that wizard is now a **Dev Console plugin** (`project-wizard`): take a GitHub repo, a VPS repo, a folder or a new AXF app; set name and description; check and pick where it lives (GitHub, VPS git, local git folder, each existing or new); then make it a Claude project with instructions and context files. It runs on `claude-project`, never a second copy of it. claude.ai has no API to create Projects, so the wizard produces a Claude.ai project kit (`_claude/claude-ai/`) and records the project's link in the manifest (`x.claudeAi.url`) once Brett pastes it back. `lib-clone` stays parked for the cross-port library and cloning with data.

- Oct 18 2026 (built on Opus): developer alerts are a **framework library** (`ai.amberx.axf.alerts`), not a console plugin, so any AXF app can install it; the engine is a cross-port contract (TS reference, Kotlin, and the console's Python server all match one fixture). Brett picked all three channels (console bell, ntfy, web push) and every source: CI failures, deploys, systems check, builds + plugins, system conflicts and crashes. Conflicts between modules (same asset id, setting key, settings id) are reported by the runtime itself as diagnostics.

## Dev Console

- Oct 16 2026: the first app is the AXF Dev Console. It tracks what's built, picks libraries to build by generating demo apps, has a feature list with suggestion dialogs, and a modules & packages tab. The first build includes only what full future scalability needs.
- Oct 16 2026: the Dev Console is a **React/TypeScript (Vite) web app with a Python (FastAPI) API**, live at console.amberxai.com. The Android console stays as the framework's Android showcase. A separate `next-ts` template exists for Next.js apps.
- Features he asked for: build tracker, feature catalog with suggestion dialogs, library picker → demo apps, modules & packages, boilerplate manager (categorized, live preview, third-party import), server control panel, build queue, pending builds, plugins, MCP client.
- Showcase features (10 layouts, 10 light/dark theme pairs, 10 style packs, the six libraries' full UIs, editor, GPS, video, VPS streaming…) come later as demo apps, one library at a time.
- Wants the console in its own private repo eventually, not yet.
- Oct 18 2026 (built on Opus, Fable rebuilds pending): **AI assistant plugin** (`ai-assistant`) — xGallery's assistant ported and extended: 18 provider kinds (Anthropic, Claude Code subscription, OpenAI, xAI Grok, Gemini, Mistral, Groq, DeepSeek, OpenRouter, Together, Fireworks, Perplexity, Cohere, Cerebras, Azure OpenAI, Ollama, LM Studio, custom OpenAI-compatible), a setup wizard in its settings tab and a settings dialog inside the chat dialog. **Agent manager plugin** (`agent-manager`) — agents built from personas, lingo, skills and tools with per-agent memory type/config, wizards (new agent, new skill, new tool, all-in-one builder, training), training from Firecrawl/URLs/repo/text/MCP on schedules, workflows (sequential/parallel/router/critic), add-on agents (coder, axf-expert, ai-expert). The two integrate only when both are installed (capability services `axf.agents@1` / `axf.llm@1`). Web console only for now; Android + other ports come with the Fable rebuilds (pending `ai-assistant-plugin`, `agent-manager-plugin`).
- Oct 18 2026: plugin settings are **sub-tabs of Settings → Plugins**, never top-level settings tabs (all five plugins moved; the console enforces it). The settings contract gained `SettingsTab.parent` (web + Kotlin) and the settings view a sub-tab row.
- Oct 18 2026 (built on Opus, Fable rebuild pending `plugin-manager`): **Plugin Manager plugin** (`plugin-manager`) with a link in the default context menu, four views (cards, table, detail, dependency graph) and four completely different layouts (Studio, Mission control, Terminal, Catalog). It opens each plugin's UI and settings when they exist (settings can also be shown inline) and notes dependencies with details. Framework additions: `AxfWebLibrary.contextMenu` / `rt.addContextItems` (+ Kotlin), `rt.refreshFromSaved`, `SettingsRegistry.reload`, per-key last-write-wins settings saves, `useEditorSync`. <!-- axf-plugin:plugin-manager -->
- Oct 18 2026: **UI-editing plugins** (theme, style, layout, manager, builder): when their saves conflict the last one wins, and whenever one opens, loads or regains focus it loads token values from current settings (rule in `rules/RULES.md`).
- Oct 18 2026: **plugin-lifecycle@1** — every plugin (these two first) can be installed and uninstalled completely so newer builds install without stale code; install scripts live in each plugin's settings tab. All future plugins follow it (see rules).
- Oct 18 2026: **Assistant sessions are always live.** Every assistant in the framework keeps its sessions open: they never close when the browser/app closes, because they run on the host (routed through axHub on the VPS); viewers attach/detach and replay. The features belong to the **assistant plugin**; the kernel only carries the contract (`live-session@1`, placeholder capability `axf.live-sessions`). Built on Opus: kernel contract on both ports + local host in the console's AI assistant plugin; axHub host is a placeholder until axHub's session workers exist. Spec `framework/spec/LIVE-SESSIONS.md`.
- Oct 18 2026: **User accounts live on axHub; the Dev Console sits behind the hub's sign-in wall** (built on Opus). Admin + more users with roles; Traefik forwardAuth at the proxy; the console token keeps working for machines on `/api/` and `/mcp`. Brett set the first admin (username `admin`) himself; the password is never stored in a repo (it goes in Coolify as `AXHUB_ADMIN_PASSWORD` for the first start only).
