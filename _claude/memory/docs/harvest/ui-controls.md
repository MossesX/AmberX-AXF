# Harvest — `ui-controls`: shared form controls, Markdown and library-parameter fields (Fable, Oct 21 2026)

Group 12 + 17 of `harvest-plan.md`. Brett chose Fable because these are shared framework components that change how
GUIs work across apps. Branch `harvest/f-ui-controls`.

## Phone summary

- The framework now owns the form kit every app and plugin had copied: **Switch, Field, TextField, SelectField,
  ChoiceGrid, Note, Section, Markdown, LibraryParamField** — same names, props and behaviour on web (React) and
  Android (Compose), theme tokens only, sized by the Spacing choice, accessible.
- New cross-port contract **library@1 parameters** (`core/library.ts` = Kotlin `LibraryParams`, fixture
  `library-params.json`); the CLI installer, the web wizard and the Android wizard now agree by test (801 checks).
- Switched to the framework versions: plugin-switches, theme-manager and the settings library toggles; the
  systems-check What's new and ai-assistant Markdown renderers (both copies deleted); the console and Android
  console `ParamField`s (deleted; the Android console's own `LibraryParam` model is now the kernel's).
- Every control shows in the web Components view / Element explorer and the Android Component gallery / explorer.
- No component-style engine input was needed: nothing here has asset-level styling, so `asset-types.json`,
  the engines and the component fixtures are untouched.

## Contracts, fixtures, registries

- `framework/core/library.ts` (exported from `core/index.ts`): `LIBRARY_PARAM_TYPES`, `PARAM_TRUE_WORDS`,
  `paramText`, `paramDefaultText`, `paramBool`, `paramToJson`, `paramError`, `paramDefaults`.
- Kotlin `ai.amberx.axf.kernel.library.LibraryParam` / `LibraryParams` (same names; `isTrue`, `toJson`, `validate`,
  `defaults`, `text`). Written without a compiler.
- Fixture `framework/spec/fixtures/library-params.json` (189 cases × 9 parameters covering every type, blanks,
  defaults, min/max, choices, list splitting on `,`/newline, every true-word). Generated by `gen-fixtures.mts`.
- Checkers: `framework/spec/check-library-params.mts` (801 checks: fixture replay **and** the CLI installer's
  `coerceParam` in `cli/libraries.mjs` agrees on every case — error ⇔ throw, value ⇔ value, blank ⇒ default) — added
  to CI (`android.yml`, console job); Kotlin `LibraryParamsTest` (runs with `:axf-kernel:test` in CI).
- `ComponentKind` (Kotlin `contract/UiKit.kt` + web `cli/ui-port.mjs` `COMPONENT_KINDS`) gained `SELECT_FIELD`,
  `CHOICE_GRID`, `LIBRARY_PARAM`, `SECTION`, `NOTE` (`MARKDOWN` already existed). Open: a kit may override them later;
  today every kit falls back to the default implementations (no `AxfComponents` slot yet, same as MARKDOWN).
- Galleries: web `Components.tsx`/`Explorer.tsx` `ELEMENTS` (34 kinds, previews for the new ones); Android
  `ElementExplorer.kt` `ELEMENTS` + `ElementPreview`, `ComponentGallery.kt` (new **Forms** and **Markdown** cards).
- Docs: `framework/spec/THEMING.md` → "Shared form controls" table; `PORTING.md` step 3 names them for new ports.

## Guards kept or tightened

- **Markdown:** both old copies built React elements only and never injected HTML. The shared renderer keeps that,
  keeps the fuller copy's `safeHref` (only `http(s):` / `mailto:` become links; anything else is plain text) and
  `rel="noopener noreferrer"` + `target="_blank"`. The systems-check copy had no links at all; it now gets links, but
  only through the same guard (tightened, not loosened: a `javascript:` target renders as text). Compose version applies
  the same `safeHref` before `LinkAnnotation.Url`.
- **Switch:** the plugin-switches lock logic (its own row greyed and never switchable, read-only when the API is
  down, busy lock while a change is in flight, confirm when a running plugin needs the one being turned off) is
  unchanged — only the drawing moved. Theme-manager's `assets.swap` gate on the Show/Hide toggle unchanged.
- **Library params:** where the three copies disagreed, the strictest wins and is now pinned by fixture:
  - the CLI accepted `y` as true, the web wizard did not (`true|yes|on|1`), Build Pilot used JS truthiness: now
    `true|yes|y|on|1` everywhere (the CLI's set, the superset);
  - Build Pilot's ParamField showed "Required" only for text params and ignored `min`/`max`/`choices`: the shared
    field validates every type like the CLI does;
  - Build Pilot's number field turned `''` into `undefined` but non-numbers into `NaN`: now "Must be a number".
- Theme rules: all new CSS is tokens-only under the strict profile (`check-theme.mjs`: 206 files, 0 problems);
  `theme-swap.mjs` on the built console: 565 elements, 0 colours that never changed, transparency follows the
  style theme.

## Visual changes (small improvements, reported)

- Install wizard (web): the field label is bold and the required `*` is red (was plain text); help text and the
  error sit under the field as before. Bool params render as a real switch instead of a native checkbox; choice
  params as choice cards instead of chips (same selection behaviour, keyboard arrow keys move within the group).
- Plugin switches: identical look (same track/thumb geometry; the framework switch reuses that CSS).
- Theme manager Show/Hide: a proper switch with "Shown"/"Hidden" text instead of a native checkbox.
- Settings → toggles and Assets in rolls: a switch instead of a native checkbox, same On/Off text.
- Components view: three new Inputs cards (Select field, Choice grid, Library parameter), two Containers cards
  (Section, Note), one Data & media card (Markdown); the Switch and Text field cards show every state.
- What's new banner / AI assistant replies: unchanged look (`.fx-md` carries the same rules the plugins had).

## Build Pilot adoption (separate repo, read-only here)

framework copy, which must be re-baked from this branch first.
