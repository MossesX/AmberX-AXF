# Application-menu hooks — differences report (Oct 21 2026, Fable)

Branch `fable/app-menu-hooks` from main `a13f9f1`. The framework half of the decision *"Console application menu
reaches everything"* (`_claude/memory/decisions.md`, Oct 21 2026): the app menu gets run-time contributions,
submenus and live lists so the toolbar and side navigation can be hidden. The console's own menu content is the
next, Opus build. **Scope change mid-build (Brett, Oct 21 2026): all Android work stopped** — web only; the Kotlin
twin is a recorded gap (`framework/spec/PORTING.md`).

## What it replaced

Before: `MenuBar` (`framework/react/components/Chrome.tsx`) drew `app-menu` asset menus as they were (`menus[].items`,
one level of flyouts through `MenuList`). Nothing could add to the menu at run time; plugins reached only context
menus (`AxfWebLibrary.contextMenu`, `rt.addContextItems`) and nav sections. No badges, checks or live lists in menus.

## Removed

Nothing. `MenuList` stays for context menus; every existing app-menu asset renders the same (fixture `developer`
cases: the real asset with no contributions passes through unchanged for every role).

## Kept

- `app-menu` asset shape (`menus[] { id, label, items }`), `MenuItem` fields, UAC `requires`, separators, shortcuts, icons.
- `filterMenu` (UAC engine) and the context-menu path, untouched.
- Hidden-slot engine, `slot.hide` action (extended, see below).

## Changed

- `framework/core/types.ts`: `MenuItem` gained optional `provider`, `badge`, `checked`, `order`, `before`, `after`;
  `AppMenuData.menus[].order`.
- `framework/schemas/asset-types.json`: new top-level `menuItems` block (optional fields, `checkedKinds`
  `setting|counter|slot|hidden`, `maxDepth` 4, `providerMax` 12, `defaultOrder` 100) — the single source for the
  engine and the validators; `app-menu.optional_fields` lists them. JSON schemas regenerated: `app-menu` and
  `context-menu` schemas now carry a recursive `$defs.menuItem`.
- Validators (`core/validate.ts` = `cli/build-engine.mjs`): menu items in `app-menu` menus and `context-menu`
  targets are checked (non-empty strings, a parsable `checked` binding, numeric `order`, no `provider` + `items`
  together, depth ≤ 4, lists of objects). The Kotlin `AssetValidator` is spec-driven and ignores the new fields, so
  Android validation keeps passing (verified: every app validates).
- `MenuBar` now draws `rt.appMenu()` (asset + contributions, gated) through the new `AppMenuDropdown`.
- `slot.hide:<type>:on|off` also takes `toggle` (the chrome toggles use it).
- Search: `SEARCH_KIND_LABELS.menu = 'Menu'`; new built-in provider `axf.app-menu`.
- `InstalledLibrary.ui.appMenuItems` (count) for the Plugin Manager.
- Icons: `more`, `hammer` added to the React icon set.
- Console: a disabled plugin's app-menu items are removed with its nav / context / settings / attachments
  (`apps/console-web/src/App.tsx`).

## Contract / API summary (what the Opus console build uses)

```ts
// AxfWebLibrary
appMenu?: { id; menu?; menuLabel?; menuOrder?; path?: (string | {id,label?,icon?})[]; order?; before?; after?; items: MenuItem[] }[]
appMenuProviders?: Record<string, (() => MenuItem[] | Promise<MenuItem[]>) | { items; max?; moreAction?; moreLabel? }>
// MenuItem extras
{ provider?: string; badge?: string; checked?: 'setting:<key>'|'counter:<name>'|'slot:<type>'|'hidden:<type>'; order?: number; before?: string; after?: string }
// runtime
rt.addAppMenuItems(c); rt.removeAppMenuItems(moduleOrId); rt.registerAppMenuProvider(id, fnOrSpec) → remover;
rt.appMenu() → { menus: [{ id, label, origin, items: CompiledMenuItem[] }], conflicts, notes };
await rt.loadAppMenuProvider(id) → CompiledMenuItem[]; rt.dispatch('slot.hide:toolbar:toggle')
```

## Migrations / compatibility

- No asset changes required. Apps that never contribute see the exact menus they had.
- Apps rendering their own menubar can keep `useAsset('app-menu')`; to see contributions they read `rt.appMenu()`.
- Baked copies (`apps/console-web/src/axf`) were re-baked in this branch; `apps/demo` keeps its older bake.

## Known gaps

- **Android twin deferred** (port on hold, Brett Oct 21 2026): `AppMenuEngine.kt`, `AxfRuntime.addAppMenuItems` /
  `registerAppMenuProvider`, `AppMenuConformanceTest`, Compose `AxfMenubar` / `AxfMenuList` with providers, badges,
  checks. The fixture is the contract to port from.
- Live lists are loaded on every open (no caching); a provider decides its own cost.
- `before` / `after` anchors resolve among siblings only; an anchor in another menu is ignored silently (sorted by
  `order` instead).
- Contributed submenu *labels* for created path steps come from the first contribution that creates them.
