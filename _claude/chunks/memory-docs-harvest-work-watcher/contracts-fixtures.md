- New fixture `framework/spec/fixtures/work.json` (generated by `gen-fixtures.mts`): contract id, poll capability,
  kinds, placeholders, delay/condition kinds, phases, event types, effects, stop reasons, the two specs (AXHub approvals,
  a back-off demo), 19 validation cases, 12 clamp cases, 4 condition cases, 11 delay cases, 5 scenarios replayed step by
  step (approvals happy path + notice spell, watching off at start / while sleeping / at wake, start-while-running no-op
  + checkNow + interval clamping, host refused, exponential streaks + fallback rule + stop outcome). Every other fixture
  byte-identical.
- Replayed by `framework/spec/check-work.mts` (129 checks: fixture + a host over the reducer, in CI) and Kotlin
  `WorkConformanceTest` (4 tests; compiled and run here with a kotlinc 2.0.21 harness against the compiled kernel: all
  pass). AXHub's `ApprovalWatchTest` pins the app's spec to the fixture's `specs.approvals` (checked here too: the app's
  spec JSON equals the fixture's).
- Placeholders: job kinds `once`, `alarm`, `constrained`, `chain`; capabilities `axf.work.manager` (the kernel's `axf.work`
  `WorkScheduler` contract on WorkManager — untouched, still the kernel's placeholder), `axf.work.alarm`, `axf.work.chain`.
  The kernel's existing `contract/Work.kt` (`WorkSpec`/`Worker`/`WorkRegistry`) is unchanged; poll jobs are a separate kind
  (a long-running foreground loop) and live beside it.
