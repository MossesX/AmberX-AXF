## Repos, servers, credentials

- **Automatic merge (Oct 30 2026, Brett: "When stuff needs to merge automatic merge"; replaces "Ready to merge = send him a merge approval", Oct 27):** PRs merge by themselves. The console's push banner auto-merges every open PR in the watched repos (AmberX-AXF, axHub, Build-Pilot by default) that is ready: not a draft, no conflicts, CI passed on its head commit (pinned) — every 3 minutes, no Claude session, no tokens (setting *Auto-merge* in Settings → Plugins → Push banner, on by default). So a session just opens the PR (`github.pulls/create` or the push banner's Open PR, a veto call) and moves on: no merge call, no asking, no checking. A repo without CI never gets a green result and never auto-merges, so every watched repo has CI (axHub: `.github/workflows/test.yml`, `pnpm test`, since Oct 30 2026). **Every change through a PR, up to date with main (Oct 30 2026, Brett: "I want everything to need a PR and to pull against main before it's merged"):** (one exception since Nov 3 2026, Brett: build status goes live — in AmberX-AXF the builds store's status-only commits from `framework/cli/builds-live.mjs` go straight to main, `_claude/` data only, never code) nothing reaches main except through a pull request — no direct pushes or merges to main, from any session, script or workflow (bots push to their own branch). The push banner (0.5.0) opens a PR for every branch ahead of main (setting *Open a pull request for every branch*, on by default), takes ready PRs oldest first, pulls main into one that is behind (head pinned) and merges it only once it is 0 behind and CI passed on that new head; at most one merge per round, so the next PR is brought up to date with the new main and re-tested first. A pull that conflicts goes to *Pull failed* / Fix with Claude. Branch protection on main (require a PR, branches up to date, the CI every PR runs) is set where the token may and never loosened; where it can't be, the systems check says why, with Auto fix. <!-- axf-plugin:push-banner -->
