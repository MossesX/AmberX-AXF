## Before building anything

- **Every UI Review submission ships options, and every option is an asset (Nov 7 2026, Brett: "Everything comes shipped (all options as assets). For UI Review, for everything sent through it, I need a minimum of three choices."):** a build submits at least **3** options for a UI (setting *Options every build ships* in Settings → Plugins → UI Review, default 3, never lower), each a predicted look plus a real asset of its type, through `review.mjs submit --name "…" --choices <file.json>` (`{ assetType, owner, options: [{ id, label, notes?, shots, data }] }`) or `choices` on `POST /api/plugins/ui-review/submit`. Every option, picked or not, is written to `apps/console-web/plugins/<owner>/assets/<type>/` tagged with its choice set, ships in the PR and shows in the asset library and in Settings → Appearance → *Choose from every asset*. Brett picks in the item's Choices tab: one option, or several in priority order where the asset type can hold several views (the first is the default; `framework/core/ui-choices.mjs` lists those types; a settings interface takes one). Build every view he picked; read it with `review.mjs decision <id> --console` or `GET choices/decision`; the build waits like any UI Review hold. With *Ask me how many options* on, run `review.mjs ask-options --build <id> --wait --console` before making them: he is asked in the console and on AmberX, no answer in time = the default. A build with a real reason for one option says it in `--single-option "<why>"`; it shows on the item. Intakes refuse a build's submission with neither. <!-- axf-plugin:ui-review -->
