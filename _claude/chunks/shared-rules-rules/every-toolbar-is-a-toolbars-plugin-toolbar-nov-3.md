## Code must conform to the asset system

- **Every toolbar is a Toolbars plugin toolbar (Nov 3 2026, Brett: "it really works on a computer"):** every existing and future toolbar, in every app, gets per-toolbar settings and the Toolbar editor through its context menu, accepts dropped hooks, and uses **tap-to-confirm on touch only**: on a finger tap the first tap shows what the button does and arms it (lit, 3 s by default, configurable), a second tap on it within the window runs it, a tap on another button re-arms that one; mouse, trackpad, pen and keyboard stay a single click with the usual hover tooltip, decided per interaction (a touchscreen laptop: finger = double tap, mouse = single click). Destructive buttons keep their own confirm on top. Switching it off for a toolbar is a setting (Settings → Plugins → Toolbars, or that toolbar's own settings), never code. In AmberX-AXF the behaviour is the framework's (`framework/react/tapConfirm.ts` on `framework/core/engines/tapconfirm.ts`, installed by `<AxfProvider>` for every element with `role="toolbar"`), and `node framework/cli/check-toolbars.mjs` fails CI on a toolbar without `role="toolbar"` and a settings id, or one that turns the behaviour off in code without `data-axf-tap-confirm-reason`. Build `toolbar-tap-confirm` (Urgent).
