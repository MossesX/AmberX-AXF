## Status (as of Oct 21 2026)

- **Build options / `--wrap-groups` (Oct 18 2026, built on Opus):** every UI build takes `--switches` from one registry, `framework/schemas/build-options.json` (`build-options@1`); each option writes an asset token, so both ports' engines read it like any other token. Drivers: `axf init … --wrap-groups` (`--x`, `--x on|off`, `--no-x`), `axf options <dir> [--framework] [--x on|off]` for existing apps, engine-rpc `init {options}` / `options` / `build-options`, `axf serve` `POST /init {options}`, `POST /options`, `GET /build-options`, console `POST /api/options`, MCP `app_init(wrap_groups, options)`, `app_options`, `build_options`, and the console's New app dialog (Build options checkboxes). **New builds start every option at its default (off)** even though the framework's starter assets have it on; `init` records them in `axf.manifest.json` → `options`. First option `--wrap-groups` → style-theme `wrapGroups` (bool, default false) → `--fx-wrap-groups 1|0`; every titled group (`Container`: React `fx-card`, Compose `AxfContainer`) gets a collapse toggle top-right (`containerCollapsible(c, style)` in `components.ts` = `ComponentStyleEngine.container` on Android: `collapsible || wrapGroups`). Turned on in every existing style theme (framework, console-web, demo, Android console). Editable live in both element explorers (Card → Wrap groups). New option = one registry entry + reading its token in the engines. `apps/demo` still runs an older baked framework, so it shows the toggles only after a re-bake.
