## Status (as of Oct 21 2026)

- **Projects, manifests and Standards (Oct 18 2026, built on Opus):** every project built with or for AmberX has `project.manifest.json` (`project-manifest@1`): `name` (= its folder on the hub, `/projects/<name>`), `displayName`, `kind`, `framework.relation` (core/built-on/for/none), `repo` (owner, name, `exists` — a repo that doesn't exist yet is still defined, for future naming), `location`, `data.shared`, plus optional fields (`x` for extensions). This repo holds four projects: `amberx-axf` (root), `axf-demo`, `axf-console-web`, `axf-console-android` (apps/); axHub has its own. Only projects built with or for AmberX (plus axHub) get a manifest and a hub folder. **Build rule: no project is loaded or compiled without a validated manifest** — `requireProject`/`checkProject` in `framework/cli/project.mjs` gate `axf validate` (and `--framework`), `options`, `install`, `new-asset`, `dev`, `import-ui` (via install), and `init` writes one from the template; every app template ships one and guards itself (react-ts: `axfProjectGuard` Vite plugin from `core/project.ts`; next-ts: `predev`/`prebuild` → `src/axf/core/project-guard.mjs`; android-compose: Gradle `axfCheckProject` before `preBuild`, runs the CLI with Node). The console and the Android console app are guarded the same way; `apps/demo` (older baked framework) is gated by `axf validate` in deploy.yml. Rules: `framework/schemas/project-rules.json` (`project-rules@1`: vocab, known keys, rules with ops equals/pattern/notIn/string/oneOf/eachOneOf/boolean/relativePaths/pathsExist/requiredWhen/knownKeys; locked rules are always errors and can't be removed or changed; rule patterns are capped at 200 characters with no nested quantifiers or repeated alternations, values over 300 characters never match, vocab entries are short lowercase words), a shared-data file, so the copy on the hub is the one in force. Validators: `framework/core/project.ts` (reference) = `framework/core/project-check.mjs` (CLI, console, guards) = Kotlin `ai.amberx.axf.kernel.project` (`ProjectValidator`, rules shipped as a kernel resource); fixtures `framework/spec/fixtures/project-manifest.json` (checked by `framework/spec/check-project-fixtures.mjs` and `ProjectManifestTest`; Kotlin written without a compiler, see the CI issue). JSON Schema for editors generated from the rules: `framework/schemas/json/project-manifest.schema.json` (`axf project schema`). CLI: `axf project validate|init|list|rules|schema` (= `node framework/cli/project.mjs …`); `axf init … --repo owner/name [--repo-exists] [--visibility] [--description] [--kind]`. Console: new nav section **Standards** → **Projects** (every project, hub folder, repo, issues) and **Manifest rules** (severity per rule, vocabularies, custom rules, try-a-manifest pad; saved through `POST /api/standards/rules`, refused when it breaks a locked rule); API `GET /api/standards/projects|rules`, `POST /api/standards/rules|validate`; MCP `project_list`, `project_rules`, `project_validate` (read-only).
