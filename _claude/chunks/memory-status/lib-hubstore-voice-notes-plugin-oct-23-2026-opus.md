## Status (as of Oct 21 2026)

- **lib-hubstore + Voice notes plugin (Oct 23 2026, Opus):** new web library **`framework/libs/hubstore`** (`ai.amberx.axf.hubstore`, feature `lib.hubstore`): an app keeps its settings and, if chosen, its data on axHub's data server instead of the device. Two classes: `HubSettings` (one `hub-settings@1` document, per-key last save wins, 409 re-merge, `mirror(rt.settings)` for the app's Settings screen; secrets never) and `HubData` (`table(name)` rows on axHub as `hub-table@1`, chunked past 64 KB; tables not picked stay on the device). library@1 parts: `settings {file, mirror}`, `data {mode all|some, tables, folder}`, so Build Pilot / `axf install --parts` picks settings only, all data or some tables. Hub down = `HubError` + state, no local copy. Test `npx -y tsx framework/spec/check-hubstore.mts` (33, in CI). First user: console plugin **`apps/console-web/plugins/voice-notes`** (`ai.amberx.axf.console.voice-notes`), a settings interface (Settings → Plugins → Voice notes) plus, since Oct 24 2026, a **Voice notes page** (view `voice-notes`, nav + Plugins menu; plugin.json `tabable`, so Patches can add it as a tab): it fetches table `notes` from axHub on show, every 30 s while visible and on focus, newest first, filter by list / subcategory, search, copy (one or as Markdown), delete (`normalizeNote`, `filterNotes`, `noteWhere`, `noteCounts`, `notesMarkdown` in `web/core.ts`; `loadNotes`/`removeNote` in the store). The settings are for a voice-activated notes pusher: start/stop/list-of-lists/cancel triggers (typed or recorded with the browser's speech recognition), beep (test button), recording limits, cut the stop trigger from text and audio, the "where should I store it" prompt, numbered lists with aliases, subcategories and question sets opened by a number or a recorded trigger, a fallback list, and a conversation preview + try-a-phrase pad; pure model + listener rules in `web/core.ts` (`stripStopTrigger`, `spokenNumber`, `pickList`, `pickSubcategory`, `pickQuestionSet`, `problems`). Stored on axHub (`settings/voice-notes.json`, `voice-notes/lists/head.json` in the amberx-axf hub project). **The listener is Voice Vault (Oct 23 2026, Opus):** `apps/voicevault/.../notes/` (app code; Kotlin twin of the rules in `NotesModel.kt`, `NotesRulesTest` = the plugin's core-check cases, in CI) reads the setup with a hub session (lib-hub `HubSignInView` + `cookieCredentials`, route `voice-notes-hub`), and the background `WakeService` hears the start triggers next to the global trigger (setting **Listen for voice notes**, Settings → Voice notes): beep, the note in turns until the stop trigger (cut, also mid-turn), "where should I store it" (number/name, list of lists read out, retries, fallback list), subcategory, question sets, saved to hub table `notes` (`voice-notes/notes/head.json`, hub-table@1 rows `{list, subcategory, text, answers, at, by, device}`), confirmation spoken. Works with the vault locked and never touches it; on-device recognition; text only (no audio kept, so `keepAudio` isn't supported on the phone). Screen **Voice notes** (route `voice-notes`, nav). Self-test `test.py` (37). Android twin of the library deferred (PORTING.md). <!-- axf-plugin:voice-notes -->
