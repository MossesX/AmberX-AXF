## Status (as of Oct 21 2026)

- **Build orchestrator plugin (Oct 27 2026, Opus):** `apps/console-web/plugins/build-orchestrator` (`ai.amberx.axf.console.build-orchestrator`), nav → Builds → **Build orchestrator**, a tab group (Builds · Approvals · Rules). Every build is steps of ≤ 30 min pinned to Fable or Opus; consecutive same-model steps = a phase; a phase that switches model waits for Brett's approval (`approve`; ticking a gated step is refused). Token rules on every build: one session, no sub-agents unless a step allows it, briefs carry only the current phase. **Levels (Oct 27 2026):** build → category → phases → groups → steps (build `category`; step `phase`/`group` labels; a phase = consecutive steps with one label and model, a gate only where the model changes; `categories()`). Builds tab has **Grid** (default; one row per build, sortable columns Build / Category / Status / Next / Steps / Left / Added, a row expands to its full card) and **List**, plus category filter chips. Builds tab = the Pending builds list's look and behaviour (pd-* cards, status strip, sort bar, step ticks, add form) plus per-step model chip (tap to switch), phases, approve switch, Copy next brief, hide/unhide, archive, import from Pending, move/remove steps, sort by time left / next model, filter next-on-model. **Tracker is a repo file** `_claude/builds/orchestrator.json` (orchestrator@1; README beside it), read and carried on by any session: `orchestrator.mjs [list|next|brief <id>|act …|where] [--json]` (`AXF_ORCH_FILE` overrides).
