## Status (as of Oct 21 2026)

- **Application-menu hooks — app-menu contributions + live lists (Oct 21 2026, Fable; web only, Android deferred):** the app menu is no longer static asset content. Engine `framework/core/engines/appmenu.ts` (pure; fixture `spec/fixtures/app-menu.json`, checker `spec/check-app-menu.mts` in CI, 113 checks): `mergeAppMenu(asset, contributions)` + `compileAppMenu(merged, env)` → one tree with stable ids, placement (`order` / `before` / `after`, default 100), menus created when missing, item paths, UAC gating (hide drops, disable locks), badges (`badge: '<counter>'` → `count`), check marks (`checked: setting:<key> | counter:<name> | slot:<type> | hidden:<type>` → `check`), live lists (`provider: '<id>'`, filled on open, capped with a More… entry), empty-submenu pruning, depth cap 4, conflicts (one id from two modules: later wins + `contribution-conflict` diagnostic; an asset item replaced by a module is deliberate). Limits/fields in `asset-types.json` → `menuItems` (single source; JSON schemas regenerated with a recursive `menuItem` definition); all validators check the optional fields (`provider`, `badge`, `checked`, `order`, `before`, `after`, `menus[].order`); the Kotlin validator is spec-driven and accepts them untouched. Runtime (web): `rt.addAppMenuItems(c)`, `rt.removeAppMenuItems(module | id)`, `rt.registerAppMenuProvider(id, fn | {items, max, moreAction, moreLabel, module})` → remover, `rt.appMenu()`, `rt.loadAppMenuProvider(id)` (async), `rt.appMenuSearchEntries()`; built-in providers `views`, `nav`, `toolbar` (items + widget actions), `settings`, `windows`, `dialogs`, `chrome` (`chromeToggleItems`: `slot.hide:<type>:toggle` + `checked: slot:<type>`; `slot.hide` now takes `toggle`). `AxfWebLibrary.appMenu` + `appMenuProviders` (installed/removed with the library; the console drops a disabled plugin's items). Search indexes contributed items with an action (kind `menu`, provider `axf.app-menu`). React: `components/AppMenu.tsx` (`AppMenuDropdown`: nested flyouts on desktop, drill-down with a Back row ≤ 480 px, loading/error/empty rows for live lists, badges, check marks, keyboard arrows/Home/End/Escape; `MenuBar` runs on `rt.appMenu()`), tokens only (`.fx-menu__check/badge/row/back`). **Android twin deferred** (`AppMenuEngine.kt`, runtime API, Compose menubar): port on hold, Brett Oct 21 2026 (`spec/PORTING.md`). The console's own menu content is the next (Opus) build. Report: `_claude/memory/docs/rebuilds/app-menu-hooks.md`.
