## Status (as of Oct 21 2026)

- **Lock the look + Get the look from axHub (Oct 27 2026, Opus; web only; pending `amberx-appearance-lock`):** AmberX looked broken (overlapping, wide-spaced text) from Settings → Appearance → Sliders saved on the device: line height could go to 5 % and **Restore default appearance didn't clear the Sliders**. Fixed: `axf.look` is an appearance setting (Restore clears it, packages carry it), line height never below 100 %, letter spacing ≤ 0.1 em (`LINE_HEIGHT_MIN`, `LETTER_SPACING_MAX` in `looktokens.ts`). New panel on top of Settings → Appearance (`axf.appearance.lock`): **Lock the look** (runtime `setAppearanceLocked`, setting `axf.lock.appearance`, not an appearance setting: `assets.swap` / `assets.import` gate as `disable` so every look control greys out, `swap` refused with a note, the device's own tweaks (Sliders, asset appearance, banner Apply to all) set aside but kept, the look from axHub still applies) and, in developer apps, **Get the look from axHub** (`setAppearanceFollowing`, setting `axf.hub.appearance.follow`: off stops the appearance source, the app runs on its own saved look with no waiting screen and pushes nothing). Both need a role that may change the look; actions `appearance.lock[:on|off|toggle]`, `appearance.hub[:…]`. Theme-switch widget, Display text size / animations and banner look editors grey out too. Five web apps re-baked (incl. `libs/settings`). CI `npx -y tsx framework/spec/check-appearance-lock.mts` (29). Android twin deferred (PORTING.md).
