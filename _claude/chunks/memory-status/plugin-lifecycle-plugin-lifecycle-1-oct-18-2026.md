## Status (as of Oct 21 2026)

- **Plugin lifecycle — plugin-lifecycle@1 (Oct 18 2026, built on Opus):** every plugin can be removed with nothing left behind, so a newer build (e.g. a Fable rebuild) installs cleanly. Code only in `plugins/<folder>/`, data only in `lifecycle.dataDir` (`.axf-console/plugins/<folder>/`), doc lines outside carry `<!-- axf-plugin:<folder> -->`, cross-plugin features only through capability services (`server/plugin_services.py`: `provide`/`get`, e.g. `axf.llm@1`, `axf.agents@1`; `GET /api/plugin-services`). Engine `framework/cli/plugin-lifecycle.mjs` (`list|status|install|uninstall [--data|--all] [--publish] [--dry-run] [--no-backup]|check [--after-uninstall]|restore`; backups in `.axf-console/plugin-backups/`); console routes `GET/POST /api/plugin-lifecycle/<folder>[/install|uninstall|check|restore]` (uninstall needs `{"confirm": "<folder>"}`, one action at a time); shared panel `src/pluginLifecycle.tsx` (`PluginLifecyclePanel`) in each plugin's settings tab; the server prunes enabled flags of folders that are gone; plugin server parts can split into modules (`axf_console_plugins` parent package). `_template` ships `install.mjs`/`uninstall.mjs`/`hooks.mjs` + the lifecycle block. Verified: removing both new plugins leaves the console building (tsc + vite) and booting, and `check --after-uninstall` clean. Older plugins (mcp-client, session-checkin, project-wizard) predate it and keep data in `.axf-console/*.json`.
