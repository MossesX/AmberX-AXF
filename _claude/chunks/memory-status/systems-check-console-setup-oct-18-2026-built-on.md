## Status (as of Oct 21 2026)

- **Systems check + console setup (Oct 18 2026, built on Opus; a plugin since Oct 18: `apps/console-web/plugins/systems-check`):** every time the console loads, `GET /api/plugins/systems-check/check` (`server/checks.py` in the plugin, console token required) checks the console token, credential file, plugins, GitHub token + repo, Anthropic API key, Hostinger API token, Coolify URL + token, axHub URL + token (live API calls with short timeouts, cached 60 s), the repo checkout, project manifest, shared data folder and `_claude/`, plus VPS host items (mosh, ufw UDP 60000-61000, Docker + container, auto-update cron, Claude Code, sign-in, claude-pick, claude-sync, session check-in, `~/.anthropic-key` perms, GitHub access, axhub-projects volume) reported by **`deploy/console-doctor.sh`** (interactive fixer on the host; `--report` runs every 15 min from `/etc/cron.d/axf-doctor`, writing `.axf-console/host-check.json`; `--fix <id>`). Issues show a banner at the top of every view (the plugin's `web/SystemCheck.tsx`, contributed through the new `AxfWebLibrary.banners`): its summary drops down the issues, its button or any issue opens the **Systems check** dialog with three views: **Grid** (expandable rows: details, fix-it-here hook, manual instructions, links), **By service** (cards per system) and **Guided setup** (dependency order, one at a time), plus **Fix all** (one issue at a time: automatic fixes run by themselves; an issue that needs you pauses the run with a prompt above the views showing its fix form or command, with Done / Skip / Stop, and continues by itself once a saved credential passes; badges queued/working/waiting for you/completed/failed/skipped; while it waits, the banner says so with Continue). Credentials typed there go to the core credential store (`server/credentials.py`, loaded at start whatever plugins are installed) in `.axf-console/secrets.env` (0600, separate from the env file install-console rewrites), loaded into the API's environment, never returned to the browser; routes `POST /api/plugins/systems-check/secret|secret/clear|check/{id}|fix/{id}` (safe server fixes only: credential-file perms, seed shared data, create `_claude/` folders; host fixes are commands to run). **Keys needed** banner (Oct 20 2026, order 8, above the setup banner): every check whose fix is a paste-it-here credential (GitHub, Anthropic, Hostinger, Coolify, axHub) that's missing or refused gets this banner instead of the setup banner; tapping it opens dialog `keys-needed` (action `keys-needed.open`) asking for exactly those keys, each tested on save (`web/KeysBanner.tsx`). It also covers the **Moshi key** (check `moshi-key`): the host doctor reports whether a key named moshi can sign in as root (`host-moshi-key`); a pasted Moshi public key (`MOSHI_SSH_PUBKEY`, not secret) is only saved, and `console-doctor.sh --fix host-moshi-key` installs it on the VPS after showing its fingerprint and asking (never from cron or the console). **Auto fix** (Oct 20 2026): every issue in the setup banner's drop-down has a button: Auto fix (runs its server-side fix), Add key, Open (settings) or Copy fix (VPS command to run on the host), plus **Auto fix all**. A fixed item stays in the drop-down for 3 s with its Fixed badge, then leaves (Oct 20 2026; `FIXED_LINGER_MS`); when the last one is fixed the banner reads "All fixed" for those 3 s and then closes. Drop-down actions are small badges (icon + word, `axp-systems-check-act`). **With Claude connected every row offers Auto fix (Oct 20 2026):** action fixes and axHub VPS fixes run as before; any other issue is handed to Mosses in the assistant (`ai.chat.start`) with the check's details, and it works only through approval cards / axHub approvals. **VPS Auto fix (Oct 20 2026):** for host checks in `server/hostfix.py` → `FIX_COMMANDS` (mosh, ufw mosh ports, `~/.anthropic-key` perms, claude-pick, Claude Code install, console reinstall for Docker/cron), Auto fix sends that exact command (plus `console-doctor.sh --report`) to axHub's `vps.run`; the approval pops up in the console showing the command, and the job runs it once approved, then re-checks (`POST autofix/{id}`, `GET autofix`).
