## Status (as of Oct 21 2026)

- **Approvals banner plugin (Oct 20 2026, built on Opus):** `apps/console-web/plugins/approvals-banner` (`ai.amberx.axf.console.approvals-banner`). A banner at the top of every view (order 5, above the systems check banners) while axHub has calls waiting for approval: count, tool + command per call (drop-down), **Review** opens the request on the hub (one waiting → its page, more → the list), ✕ hides it until something new arrives. The browser reads axHub's `GET /auth/admin/approvals.json` (axHub decision #85) directly with its own hub session cookie; the console server never sees the session, and only signed-in hub admins get data (signed out / not admin / console-token-only → no banner). Polls every 5 s while visible and on focus; links are used only if they point at the hub. Never approves. **Opens by itself (Oct 20 2026, axHub decision #87):** each new request opens once in dialog `approvals.review`, the hub's own approval page in a sandboxed frame (hub setting `AXHUB_APPROVALS_FRAME_ANCESTORS=https://console.amberxai.com`); it closes once decided; switch "Open new approvals by themselves" (per browser) in its settings. Settings → Plugins → Approvals banner (status, Check now, open the page); actions `approvals.check`, `approvals.open`. Web-only, no server part. <!-- axf-plugin:approvals-banner -->
