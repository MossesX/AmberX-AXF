## Status (as of Oct 21 2026)

- **Boilerplate screenshots (Oct 20 2026, built on Opus; for Build Pilot's boilerplate rows):** boilerplate@1 takes optional `screenshots: [{file, screen?, caption?}]`, files in `framework/boilerplates/<id>/screenshots/` (PNG/JPEG/WebP, plain names, ≤ 5 MB, no SVG). Console `GET /api/boilerplates/<id>/screenshots/<file>` serves them (admin/console token; refuses links, traversal, other types). None captured yet; Build Pilot renders screens from their kinds meanwhile. Spec in `framework/boilerplates/README.md`. **Captured by CI (Oct 20 2026):** workflow `boilerplate-shots.yml` (manual, input `boilerplates` = ids or `all`): per boilerplate `axf init` an android-compose app, `gradle :app:assembleDebug`, run on an API 34 emulator, `framework/cli/boilerplate-capture.py` taps each screen in the app's own nav (tabs/rail/drawer, via uiautomator) and screencaps it (demo-mode status bar, 540 px wide); job `file` runs `framework/cli/boilerplate-shots.mjs apply` (verified captures only; a run with nothing verified keeps the old ones) and pushes `[skip ci]`. Screens are still placeholder views, so captures show the real shell, theme and nav around them.
