## Status (as of Oct 21 2026)

- **Developer alerts library (Oct 18 2026, built on Opus):** `framework/libs/alerts` (`ai.amberx.axf.alerts`), engine `framework/core/engines/alerts.ts` (alert@1) = Kotlin `ai.amberx.axf.kernel.alerts.AlertEngine` = Python `apps/console-web/server/alerts.py`, all replaying `spec/fixtures/alerts.json` (Kotlin `AlertConformanceTest`, written without a compiler: check the CI issue). One alert per key (default `source:title`): repeats bump count/time and keep your acknowledgement, a worse severity escalates, a resolved alert reopens; delivery rules per channel (`bell`, `ntfy`, `webpush`, open set) = lowest severity + per-source overrides/`off`; phones hear only new/escalated/reopened (defaults: bell info+, phones error+). Runtime **diagnostics** (`rt.diagnostics`, TS + Kotlin): asset id registered again by another origin with other content (`register(raw, source, origin)`), two modules with the same setting key or settings tab/group/panel (settings tabs now carry `module`), crashes; kept (last 100) for late subscribers. **Badges:** `rt.setBadge/badge`, toolbar items take `badge: "<counter>"` (both ports); the console's bell (`alerts.open`, `alerts.unread`) is on the banner since Oct 21 2026 (`alerts-bell` plugin; it left the toolbar). Library: Alerts view (filters, ack/resolve/dismiss, links `view:`/`settings:`/https), Settings → **Alerts** (rules grid, sources, ntfy server/topic/token, web push per device, test), page-crash capture (10/min cap), transports (`localTransport` default; console `src/alertsTransport.ts`, live via fetch-streamed `/api/alerts/stream`, token never in a URL). Web push service worker `libs/alerts/alerts-sw.js`, served as a real file by `alertsServiceWorker()` (`libs/alerts/vite-plugin.mjs`; Vite would inline it as a data: URL). Console server: `/api/alerts` (+ `/ack`, `/resolve`, `/dismiss`, `/stream`, `/config`, `/test`, `/webpush/subscribe|unsubscribe|test`, `/poll`, `/deliveries`; console token on all), store + config + secrets + subscriptions + VAPID key in `.axf-console/alerts*.json|pem` (0600), sources every 3 min (configurable): GitHub Actions on watched repos (`ci`; `deploys` when name/file says deploy; once per failing run, resolved by the next green run, deploy successes after the first look), systems check (error/warn ↔ resolved on ok), pending list status changes (failed/broken/complete), plugin load errors + duplicate plugin ids, API crashes (middleware) and unclean restarts (`alerts-run.json`); browser sends conflicts and page crashes. ntfy = JSON publish (any server, optional token); web push implemented directly (RFC 8291 aes128gcm + RFC 8292 VAPID ES256 on `cryptography`, no pywebpush: its http-ece build fails). CI: `framework/spec/check-alerts.mts` + `server/test_alerts.py` (decrypts a pushed message like a browser). Guards (after an independent review): a conflict is reported only when two *named* modules (`origin`) register the same asset id with other content (apps and imports overriding a built-in are deliberate); API crash alerts come from an exception handler (not HTTP middleware), keyed by route template, max one per key a minute and 20 per 10 minutes, raised off the event loop; the phone queue is bounded (100); ntfy gets title + link only unless "Include details" is on; ntfy servers must be https (http only on loopback) and no request follows redirects (tokens); push payloads are UTF-8 and capped at 3000 bytes; seen CI runs persist (`alerts-seen.json`) so a dismissed failure doesn't return after an update; damaged stored alerts are dropped on load; `spa()` no longer crashes on overlong paths; `install-console.sh` runs `docker stop` before `docker rm -f` and the image `exec`s uvicorn, so updates are clean shutdowns (no false "unclean restart"). Not yet: an Android alerts library/UI (kernel contract, asset-conflict diagnostics and toolbar badge only; setting/tab/panel conflicts aren't reported on Android), FCM/UnifiedPush for app users, MCP tools for alerts.
