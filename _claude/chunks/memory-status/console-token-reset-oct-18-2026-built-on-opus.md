## Status (as of Oct 21 2026)

- **Console token reset (Oct 18 2026, built on Opus):** `POST /api/token/reset` (`{"confirm":"reset"}`, needs the current token; 409 when no token is set) issues a new 32-char token, rewrites the `AXF_TOKEN` line of `.axf-console/env` (0600, other lines kept), closes open terminal sessions and returns the token once (`no-store`). The server reads the token through `current_token()`, which prefers that env file over the `AXF_TOKEN` env var and re-reads it on change, so a reset applies at once to the API, `/mcp`, plugin routes and the terminal and survives restarts. UI: **Reset token** under the token field in the panel (Connection) and in the console (Settings → Account & security → Console token); both save the new token in that browser. `install-console.sh` now lets `AXF_TOKEN=… bash install-console.sh` replace the saved token (before, the saved one silently won).
