## Status (as of Oct 21 2026)

- **Console behind axHub's sign-in wall (Oct 18 2026, built on Opus; axHub decision #77):** `deploy/install-console.sh` step 6 adds Traefik labels to the console container: a headers middleware that strips client-sent `X-Auth-User/Role/Via`, then forwardAuth to `https://axhub.amberxai.com/auth/verify` (`AXF_WALL_HUB` overrides). Only signed-in **admins** of the hub get in; browsers without a session are sent to the hub's sign-in page and back. Requests with `Authorization: Bearer` on `/api/` and `/mcp` pass the wall, so the console token keeps working for MCP, CLI and the console's own API calls (the console still checks it). It switches on only when the hub's login page works and has an account (until then a `wall-waiting` marker makes the 5-minute update retry), then saves `on` so a hub outage blocks the console instead of opening it. `AXF_WALL=off bash deploy/install-console.sh` turns it off (saved in `.axf-console/wall`; the way back in if the hub is down), `AXF_WALL=on|auto` back on. When the hub lets a request through on a bearer header (`X-Auth-Via: token`), the console's `_wall_token_gate` middleware requires the real console token on **every** route, reads included. **Signed-in hub users (Oct 18 2026):** with the wall on the installer sets `AXF_TRUST_WALL=1`; `server/wall.py` turns the wall's `X-Auth-User/Role/Perms` into `request.state.axf_user` **only with a valid `X-Auth-Sig`** (HMAC-SHA256, ≤ 120 s, this host; secret in `.axf-console/wall-secret` → `AXF_WALL_SECRET`, made by the installer, must equal `AXHUB_WALL_SECRET` on the hub) — anything on the Docker network could otherwise reach the console without the proxy. A hub **admin** browser counts as the console token everywhere (no pasted token needed); a hub **user** reaches only plugins with `"wallUsers": true` (the installer opens their `/api/plugins/<folder>/` at the wall via `/auth/verify?user_paths=…`). Browser-session writes need the console's own Origin. Without `AXF_TRUST_WALL=1` those headers are ignored. **Hub users in the console (Oct 18 2026, built on Opus; axHub decision #81):** with the wall on, the installer opens the whole console to every signed-in hub user (`user_paths=/`; `AXF_WALL_USERS=off` = admins only, saved in `.axf-console/wall-users`) and passes `AXF_WALL_HUB`. The console server is **default-deny** for users (`_wall_user_gate` + `wall.user_may`): the page, a GET allowlist of framework data (`USER_READ_PATHS`: catalog, tracker, plan, pending, plugins list …) and the routes of plugins they're granted: only plugins whose plugin.json says `"userGrantable": true` (every route safe for a non-admin: theme manager, Claude badge) and only with the exact hub permission `console.plugin.<folder>` (wildcards never open a plugin), plus `wallUsers` plugins; every other plugin, every write, the terminal and all WebSockets, alerts, secrets, plugin on/off, `/data/*`, `/panel` and MCP stay admin-only; a session header that doesn't parse is refused, never treated as anonymous (independent security review, fixes in the same change). `GET /api/me` (name, role, perms, `role` admin/themes/user, granted plugins); `/api/plugins` shows ungranted plugins as off. UI (`src/account.tsx`): the runtime binds to the account (`rt.bindPrincipal` = Kotlin `AxfRuntime.bindPrincipal`, new on both ports: refuses `setRole` and uac-policy swaps while bound, keeps the account's role through reset/refresh) under the console's `console-access` policy (admin `*`; themes = `assets.swap`+`assets.import` when granted `console.themes`; user = nothing), so theme, colour, layout and style settings (now incl. Spacing) are locked for users without the grant. Settings → Account & security → **Your account** (name, role, granted plugins, links to the hub's account page and sign-out) and **Account management** (admins: link to the hub's users page, every grantable permission with Copy, the `AXHUB_PERMISSION_HINTS` value). Test `server/test_wall_users.py` (53 checks, in CI). The spacing action now needs `assets.swap`, and importing a uac-policy is refused while signed in (both ports). Security review also found and fixed a path traversal in the SPA fallback (commit 011ae2a): **rotate `AXF_TOKEN` and `GITHUB_TOKEN`**, they may have been readable.
