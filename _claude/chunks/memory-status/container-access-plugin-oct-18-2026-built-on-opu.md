## Status (as of Oct 21 2026)

- **Container access plugin (Oct 18 2026, built on Opus):** `apps/console-web/plugins/container-access` (`ai.amberx.axf.console.container-access`). The only console code that touches other containers, through `axf-docker-proxy` (haproxy, `deploy/haproxy.cfg` in the plugin: list/inspect, archive GET/HEAD/PUT, exec, restart only; everything else 403), started by `deploy/install-console.sh` via the plugin's `deploy/host.sh` (private network, `AXF_DOCKER_PROXY`; sidecars labelled `axf.plugin=<folder>` are removed once a plugin folder is gone). Protected list enforced server-side and locked: Coolify, Traefik/coolify-proxy, the console, the proxy, databases (+ your own patterns); reach all or a list. Audit log of every write/delete/exec/restart/redeploy/restore/terminal. Change batches (`change-batch@1`): agents only propose; you approve (or untick) on a card (`src/changeBatch.tsx`), one snapshot per container first (`axf.snapshots@1` required), applied in order, stops at the first failure, refuses files changed since proposed; undo restores the batch's snapshots. Provides `axf.containers@1`. Settings → Plugins → Container access. Review fixes (Oct 18 2026): exact base hash up to 20 MB (bigger files refused), unseen changes need an explicit accept on the card, commands need snapshot paths, undo locked to finished batches; agents never read secrets files in containers (`.env`, keys, `/proc`, …) and secret-looking values are redacted. **Known limit:** the Docker proxy can't tell containers apart, so the protected list is enforced in Python only and anything running code in the console container is host-root equivalent (filtering proxy not built).
