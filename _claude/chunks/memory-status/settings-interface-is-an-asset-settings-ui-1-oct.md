## Status (as of Oct 21 2026)

- **Settings interface is an asset — settings-ui@1 (Oct 23 2026, Opus; Fable rebuild parked as `settings-asset-fable`):** new optional asset type **`settings`** (group System, not rolled) so several apps share one settings interface with the same options: `layout` tabs-top / tabs-side / list (drill-down), `header` full / compact / none, `search` (filter over every setting), `descriptions`, `tabs` (order, relabel, re-icon, new tabs, `hidden`), `hide` (tab / group / panel / setting ids) and `groups` of data-only options (toggle, text, number, slider, choice, multi_choice, color, link, section; values under the same keys in every app). Engine `core/engines/settingsui.ts` (`normalizeSettingsUi`, `settingsUiErrors`, `arrangeSettingsTabs`, `filterSettingsGroup`, `settingsUiGroups`, `settingMatches`); `SettingsRegistry.removeTab`. The web settings library (`framework/libs/settings`) renders from the active asset and registers its tabs/groups (module `asset:settings/<id>`), swapped live from Settings → Appearance → Settings interface. Starters `standard` (default = the page as before), `side-tabs`, `developer-apps` (side tabs + search + a shared Developer tab); defaults + console-web / axhub-web / walkthrough-studio manifests name `standard`. Fixture `spec/fixtures/settings-ui.json`, CI `npx -y tsx framework/spec/check-settings-ui.mts` (25). Android twin deferred (PORTING.md). Not screenshot-verified. **One settings interface for every app (Oct 25 2026, Opus; pending `shared-settings-interface`):** framework asset `settings/console` (the console's settings interface) is the default of every web app with settings (console-web, axhub-web, patches-web, walkthrough-studio, amberx-droid), and each ships the same four settings assets (console, standard, side-tabs, developer-apps; the per-app `axhub-web`/`patches`/`amberx-droid` ones are gone). Settings → Appearance → **Settings interface** panel (`SettingsInterfacePanel` in `libs/settings`): every interface with its layout, the one in use marked, Use = `rt.swap('settings', id)`. The pick is a normal slot in axHub's appearance document, so a change in one developer app shows in all of them live. Those four apps were re-baked. **Asset appearance section + settings toolbar asset (Oct 25 2026, Opus):** Settings → Appearance → **Assets** now only picks each slot's asset; a new **Asset appearance** section (panel `axf.asset-appearance`, laid out the same: one collapsible card per slot) holds every per-asset appearance editor. settings-ui@1 gained optional `toolbar` (a toolbar asset id): the settings page draws that asset as its own toolbar (`AssetToolbar` in `react/components/Chrome.tsx`, same items/gating as the app toolbar; its search spot is the settings search). Starter `toolbar/settings-page` (Appearance, Account, Plugins, About, Restore look, search; `roll: false`), named by `settings/console` 1.2.0 in every app.
