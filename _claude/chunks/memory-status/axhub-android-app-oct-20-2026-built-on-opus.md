## Status (as of Oct 21 2026)

- **AXHub Android app (Oct 20 2026, built on Opus):** `apps/axhub-android` (`axhub-android`, package `ai.amberx.axf.axhubandroid`, repo name reserved). Puts axHub approvals on Brett's phone: sign in once in an in-app web view locked to the hub's address (no JS, no off-hub navigation, session never backed up); a foreground service (`specialUse`) polls `GET /auth/admin/approvals.json` with that session every 30 s and raises one high-priority alert per new approval, full screen when allowed; tapping opens that approval's hub page in the app, where he approves on the hub's own page (hub Origin + CSRF apply). Never over the lock screen; lock-screen text is just "Approval waiting"; FLAG_SECURE; app lock via lib-lock (fingerprint by default, fails closed; sign-out-and-reset escape that also ends the hub session). Watching turns on after the first sign-in unless chosen; signed out = checks every 5 min. **Apps** tab = the hub's app catalog with downloads. **Auto-approve (Oct 22 2026, Opus; Brett asked for it despite the Android hold):** AXHub → Settings → AXHub → **Auto-approve** (off by default) + **Auto-approve tools** (`vps.logs, github.*`, `*` = everything, empty = nothing); the watcher approves a matching new approval on the hub's own form (session cookie, hub Origin, page CSRF, only the hub's `ok=approved` answer counts, otherwise the normal alert) and posts "Auto-approval approved <tool>" on its own channel (lock screen: just "Auto-approval approved"). Code `watch/AutoApprove.kt`, test `AutoApproveTest`. Boot/update restart (since Oct 21 2026 the service, back-off and restart are the framework's lib-work; the app registers one `ApprovalWatch` job). Planned areas (services, jobs, audit, vault names, users, projects, devices) are routes with placeholders; placeholder capabilities `axhub.admin-api`, `axhub.push`, `axhub.agent`. CI: `:app:testDebugUnitTest :app:assembleDebug`, artifact `axhub-debug.apk`. Written without a compiler: check the "CI build errors" issue.
