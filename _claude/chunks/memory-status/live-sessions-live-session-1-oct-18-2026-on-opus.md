## Status (as of Oct 21 2026)

- **Live sessions — live-session@1 (Oct 18 2026 on Opus; Fable rebuild Oct 20 2026 with `ai-assistant-plugin`):** rule: every assistant in the framework keeps its sessions live — a session is owned by its host, never by the browser; closing a tab/app only detaches, any device reattaches and replays; a session ends only when closed on purpose. Kernel contract unchanged (`framework/core/live-session.ts` = Kotlin `ai.amberx.axf.kernel.live`, fixtures `spec/fixtures/live-session.json`); spec `framework/spec/LIVE-SESSIONS.md`. The Python host side is `framework/python/axf/assistant_host/sessions.py` (harvested from the plugin Oct 21 2026): an **open host registry** (`SessionHosts`, mirroring the kernel's): `LocalHost` built, `axhub` a typed `PlaceholderHost` (never pretends to work; the chat falls back to local with a notice); a plugin providing **`axf.live-host@1`** or calling `axf.live-sessions@1.register_host()` adds a real host and the chosen one runs the same turn engine. A console restart mid-reply marks the turn `interrupted` **and keeps the streamed text** as an interrupted message (setting `keepInterrupted`, Continue button). Routes unchanged (`/sessions`, `/sessions/{cid}`, `/sessions/{cid}/events`, `stop`, `close`, 409 while running). **Hub users** unchanged: `wallUsers`, `assistant.*` permissions, admin-only write mode, per-user daily caps (now editable in Behaviour, totals in Usage), one running reply per user. Not yet: axHub session workers, Android assistant UI (kernel contract + `AssistantClient` only), resuming a reply mid-generation. <!-- axf-plugin:ai-assistant -->
