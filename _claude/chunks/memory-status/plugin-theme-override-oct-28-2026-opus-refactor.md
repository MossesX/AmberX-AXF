## Status (as of Oct 21 2026)

- **Plugin theme override (Oct 28 2026, Opus; refactor-all s72–s75, branch `refactor-all/plugin-theme`):** every plugin UI gets its own theme override over the app's (axHub) theme. Framework library `framework/libs/plugintheme` (`ai.amberx.axf.plugintheme`, web only): setting `axf.plugin.<pluginId>.look = { on, tokens: { "--fx-…": value } }` (only changed tokens, checked per kind); every plugin UI root carries `data-axf-plugin="<id>"` (views, dialogs, window / tab-group tabs, its settings tab via `SettingsTab.plugin` in `TabContent`, its panels; `.fx-plugin-scope` = `display: contents`) and one stylesheet (`#axf-plugin-theme`) re-declares the overridden vars there; the appearance lock sets it aside; the editor itself always draws with the app's values. Console `underPlugins` wraps every plugin with `withPluginTheme` (no per-plugin code): Settings → Plugins → <plugin> → **Appearance** (Theme override switch; collapsible container: grouped form, token tree with tri-state groups + search, raw JSON, copy from another plugin / colour or style theme asset, reset per token / group / all, live preview). Switch it from right-click inside a plugin UI (`rt.contextExtras` `*:plugin-theme`), the toolbar button (action-button `plugin-theme`, setting `axf.pluginTheme.toolbar`) and Plugins ▸ All plugins ▸ <plugin> ▸ Theme override (plugins-menu; action `plugin-theme.toggle:<id>`, counter `plugin-theme.on:<id>`). Framework: `Checkbox indeterminate`, `ColorField`. Not a cross-port contract (Brett skipped the Fable plugin-theme@1 steps): `_claude/memory/docs/plugin-theme-override.md`.
