- **Codebase changes plugin (Oct 21 2026, built on Opus):** `apps/console-web/plugins/codebase-changes` (`ai.amberx.axf.console.codebase-changes`). Every request to Claude to build, edit, remove or fix something is an entry (`change-log@1`: kind, title, what was asked (cut short, secrets hidden), repos, model, who/where, steps `{text, state queued/running/done/failed/skipped, startedAt, finishedAt, note}`, result `{state done/failed/partial/cancelled, summary, branch, commits, filesChanged, tests name→before/after, links}`, `closed {at, by}`); schema `schema/change-log.schema.json`, validators `changes-core.mjs` = `server/store.py` (test.py runs both on the same cases). **Stored on axHub:** one file per entry at `changes/<YYYY>/<MM>/<id>.json` in the shared data folder (`/projects/amberx-axf/_data/changes` in the console container; `changes/` added to the root manifest's `data.shared`, repo copy = synced snapshot; 0660/2770 in the hub tree so axHub can read it, atomic writes; no shared index file, the server indexes the files). **Recording:** `changes.mjs` (`open|step|result|close|reopen|list|show|where|flush`; writes to `AXF_CHANGES_DIR` → the shared folder → the console API with `AXF_TOKEN` → `--to-repo` → a local 0700 queue `~/.axf-changes/queue` flushed later) and its Claude Code hook (`changes.mjs hooks install`: `UserPromptSubmit` opens an entry when the prompt asks for a change (documented keyword classifier, questions skipped, idempotent per session + prompt) and prints the id + commands into Claude's context; `Stop` finishes running steps; `SessionEnd` skips queued ones and marks a result-less entry partial; always exits 0).
