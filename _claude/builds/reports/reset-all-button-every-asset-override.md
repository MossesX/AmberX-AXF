# Reset all button for every asset override in Appearance

Build `reset-all-button-every-asset-override` (Opus), branch `claude/reset-all-button-every-asset-override`.
Brett (Nov 16 2026): "I want to reset all, all. Button."

## Result

Settings → Appearance → "N assets are controlled by their own settings" now has a **Reset all** button. It shows only
when N > 0, asks once ("Reset all N asset overrides? … You can undo it."), resets everything in one settings batch,
shows one toast, and leaves an inline **Undo reset all**. The per-row buttons that also said "Reset all" now say
**Reset** (they reset one asset; aria-label "Reset <asset>"), so the two actions no longer share a name.

UI Review: item `r-20261116-sjk8l01`, waiting for Brett. Three placement options (ui-choices@1, `toolbar` assets in
`apps/console-web/plugins/theme-manager/assets/toolbar/`): header with Reset all on the right, header toolbar with a
count chip, overflow-menu item. What ships now is closest to the count-chip option without the chip.

## Plan (s1): what chrome.reset clears

| Key | Meaning | chrome.reset | Reset all |
| --- | --- | --- | --- |
| `axf.chrome.<type>.<instance>` | field overrides over the active asset | yes | yes |
| `axf.chrome.<type>.<instance>.asset` | the asset a tab group picked for itself | yes | yes |
| `axf.chrome.<type>.<instance>.interface` | that instance's own settings interface | yes | yes |
| `axf.tokens.instances` → `tabs.<instance>` | the tab row's own component tokens | no | yes |

chrome.reset had no undo and cleared its keys one at a time (three change events). It now clears them in one batch.
`axf.chrome.*` is device-local; `axf.tokens.instances` rides the axHub look, so the token part of a Reset all reaches
every app.

## What changed

  `resetAllPlan(saved)` → `{ ids, clear, set, snapshot }`, `undoResetAllPlan(snapshot)`, the undo ring
  `pushResetAllUndo` / `findResetAllUndo` (`axf.chrome.reset-all.undo`, newest 5), `CHROME_TOKEN_FAMILY`.
  Fixture `spec/fixtures/chrome-settings.json` → `resetAll` (generated by `spec/gen-fixtures.mts`). Kotlin twin
  recorded as deferred in `spec/PORTING.md`.
- **Settings store** `framework/core/settings.ts`: `SettingsRegistry.batch({ set, clear })` — one storage write, one
  re-render, each touched key announced once (so the axHub look push still follows `axf.tokens.*`).
- **React** `framework/react/components/ChromeContext.tsx`: `resetAll(rt)`, `undoResetAll(rt, id)`,
  `overridesState(rt)`, `resetChrome(rt, type, instance)` (exported next to each other); actions `chrome.reset-all`,
  `chrome.overrides`, `chrome.overrides-undo` (appended to `CHROME_ACTION_IDS`); an always-on console-control target
  `setting:appearance.asset-overrides.reset-all` (state = count, rows, undo ids; press = Reset all, needs confirm);
  `AssetsWithEdits` header as a `role="toolbar"` row (`aria-label="Asset overrides"`, `data-axf-target` = the address).
  The list now counts own asset / interface picks and own tab tokens too, so what is listed is what Reset all clears.
- **Theme manager** server: `GET /overrides`, `POST /reset-all` (`{"confirm": true}` or 409), `POST /reset-all/undo`.
- **CLI** `framework/cli/chrome-settings.mjs overrides | reset-all --confirm | undo <id>`; `axf console overrides |
  reset-all --confirm | reset-all-undo <id>`.
- **Voice** (`core/engines/console-control-voice.mjs` + its Python twin in `apps/console-web/server/console_control.py`):
  "reset all asset overrides" (asks for confirmation), "… confirm" / "confirm reset all …", "undo reset all",
  "show my asset overrides". Voice commands now carry `confirm`.
- **Help / glossary**: five framework help entries (button, undo button, three actions).
- **Baked**: console, axHub web and Molly carry the new framework files (lock entries updated); shared help asset
  re-baked into every shared-assets app; walkthrough-studio's help copy synced.

## How it is reached (API parity)

| Surface | How |
| --- | --- |
| Deep link | `view:settings/tab:settings.tabs=appearance/setting:appearance.asset-overrides.reset-all` (console_open / console_show) |
| Console action | `chrome.reset-all:confirm`, `chrome.reset-all` (asks first), `chrome.overrides`, `chrome.overrides-undo:<id\|last>` |
| console-control | `state` / `press` (confirm) on `setting:appearance.asset-overrides.reset-all`; `function:chrome.*` |
| REST | `GET /api/plugins/theme-manager/overrides`, `POST …/reset-all` `{confirm:true}` → `{reset, undoId}`, `POST …/reset-all/undo` `{undoId}` |
| MCP | plugin-commands (static route reading): theme-manager `overrides`, `reset-all`, `reset-all-undo`; `console_control_*` tools on the address |
| CLI | `node framework/cli/chrome-settings.mjs overrides \| reset-all --confirm \| undo <id>`, `axf console overrides \| reset-all --confirm \| reset-all-undo <id>` |
| Voice | "reset all asset overrides" → asks; "reset all asset overrides confirm" → does it; "undo reset all"; "show my asset overrides" |

Address note: the build asked for `setting:appearance/asset-overrides/reset-all`; the console-control grammar needs
`kind:id` for every segment, so the address is `setting:appearance.asset-overrides.reset-all`.
