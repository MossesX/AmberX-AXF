# Auto-land: merge main and land (land.mjs clash)

Build `auto-land-merge-main-land-land-mjs-clash` (Opus, phase 1). Brett, Nov 13 2026 23:38: "land what finished".

Branch `claude/auto-land-every-finished-build-lands`, PR [#660](https://github.com/MossesX/AmberX-AXF/pull/660), in the merge queue.

## What clashed
`git merge origin/main` stopped on one file: `apps/console-web/plugins/push-banner/land/land.mjs`. Everything else merged cleanly
(land-core.mjs, land.test.mjs, THREADS.md and the builds files).

- **Main** (build lander-regenerates-generated-files-clash) added `resolveConflicts`, which settles conflicts using the
  generated-files@1 manifest (`framework/spec/generated-files.json`). Builds files take main's side. THREADS, logs and
  PORTING are unioned. Help packs and catalog status are merged as JSON. Generated files take main's copy, then their
  generator runs on the merged tree, followed by its check and the land tests. Main also added `land.mjs merge-main <build>`.
- **This branch** added the sweeper (`sweep`), the serial landing line (`serial`, `lock`, `--wait-lock`), the per-build
  switch (`off`, `on`), `line`, `badJson`, and `refreshRunning`, which merges main into running builds in place
  (`mergeMain({ inPlace })`).

## How both sides were kept
- `mergeMain({ s, git, b, dry, inPlace, log })` uses main's `resolveConflicts` for every conflict. It keeps the branch's
  in-place worktree mode for running builds and its JSON check after settling (`badJson`: a file that doesn't parse takes main's copy).
- The CLI keeps both sets of commands: `line`, `sweep`, `lock` and `serial` from the branch, plus main's `merge-main`.
- The merge queue imports `mergeMain` and `resolveConflicts` from land.mjs, so it uses the same rules as before.
- Status files (`_claude/builds/*`, THREADS live log) are main's copy plus this build's THREADS row. tracker.json is
  regenerated by its generator instead of hand-merged.
- No helper is duplicated or orphaned. `regenFor` is main's own and still has main's tests. The two `kickReason`
  functions live in different modules and mean different things.
- Main's three framework files named the plugin folder (land-resolve.py, BUILDS.md, generated-files.json). The
  push-banner lifecycle check failed on them, so they were reworded.

## Sweeper → regenerate path (s4)
When a finished build's clash names only generated or data files (land-core `regenFirst`: no code file in the list), the
sweeper now merges main in again through `mergeMain`. `resolveConflicts` regenerates the generated files there. It does
this at most once per head, before filing a fix build.
- Merged: pushed, and the build goes first in line (`now`).
- Still clashes in code: the P0 "Merge main and land" fix build is filed, naming the code files.
- Real source clash: straight to the fix build, as before.

## How the sweeper is reached (s5)
| What | REST `/api/plugins/push-banner` | MCP (plugin-commands@1) | CLI `land/land.mjs` | Voice (AmberX, control@1 `plugins.commands` / `plugins.reads`) |
|---|---|---|---|---|
| State: paused, last sweep, what it did, stuck | `GET /land/status` (new) | `push_banner_land_status` (new) | `status` (new) | `push-banner/land-status` |
| Landing line | `GET /land/line` | `push_banner_land_line` | `line` | `push-banner/land-line` |
| Run now | `POST /land/sweep` | `push_banner_land_sweep` | `sweep` | `push-banner/land-sweep` |
| Pause / resume | `POST /land/pause {why?}`, `POST /land/resume` (new) | `push_banner_land_pause` / `_resume` (new) | `pause [--why]`, `resume` (new) | `push-banner/land-pause` / `land-resume` |

Pause only stops the timed 10-minute sweep. Rounds still land and the merge queue still merges. A sweep asked for on any
channel still runs. All four channels go through one implementation (land-core `applyControl` and land.mjs `sweepStatus`).
There is no new UI.

## Incident during the build
At 23:44 UTC a job on the VPS ran `git prune --expire=now; git gc --auto` in `/opt/axf` while other git work was running.
That deleted objects the shared repo still needed: main's tree, and later fetches failed with "unresolved deltas". Every
worktree under `/root/axf-builds` uses that object store. This build moved to a fresh clone
(`/root/axf-builds/auto-land-clash-clone`) and pushed from there. The shared repo needs `git fetch --refetch origin`
(or a fresh clone), and the job that prunes with `--expire=now` should stop doing that.

## After it lands
Auto-land stays on for every build. Each finished build is merged with main, regenerated where only generated files
clash, given a PR and queued with the rest as one batch. The 10-minute sweeper picks up anything that stalls: kick-outs
and clashes get a P0 fix build, stuck pushes go first in line, generated-only clashes are regenerated. Every finished
build lands by itself. Nobody merges by hand.
