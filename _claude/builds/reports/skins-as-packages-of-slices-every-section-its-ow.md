# Skins as packages of sections (build `skins-as-packages-of-slices-every-section-its-ow`)

Branch `claude/skins-as-packages-of-slices-every-section-its-ow`, PR #446. Phase 1 Fable (s1), phase 2 Opus (s2, s3).

## Brett said (Nov 10 2026, verbatim)

> For each section in skins, like colors, layouts, design, behavior, you need to be able to save each individual section
> as a new asset, then build your skins with these assets. Drag one from the list into a template that has all the
> categories a pack needs, build an entire skin, export it as a new skin, apply it. Make it sick. Every skin has to be a
> package of chunks. Every single thing has to be its own asset. It can't be one. Every section must be its own chunk.
> When you're building a new one, or enabling or changing one, you can select which sections you want taken in and which
> ones left out. When you apply a theme, you can leave certain things out, and when those mix with the existing theme, it
> asks you to create the new skin, in a dialog.

## What he asked for, and where it is

| Ask | Where |
| --- | --- |
| Every skin is a package of chunks; every section its own asset | skin-sections@1 (`framework/core/engines/skin-sections.mjs`): a skin manifest names one asset per section (colours, design, layout, behaviour, typography, density, sizing, icons, controls, chrome, parts). New asset types `chrome-set` and `style-parts`. Every shipped skin and design package converted; `check-skin.mts` fails on any monolithic one. |
| Save each section as a new asset | Skin Builder slot → "Save as asset"; `POST …/skins/sections`; `skins.mjs save-section`; MCP `theme-manager_skins_sections`. |
| Drag from a list into a template with every category | Skin Builder (Theme manager, view `skin-builder`): slice library (search, by section, hover preview) + pack template, one slot per section; drag on desktop, Pick → tap on phone; empty / required slots highlighted. |
| Build, export as a new skin, apply | Save / Apply / Export (skin-package@1 with the section assets inside) / Import / Duplicate / Load; `skins.mjs build`, `export`, `import`; REST `…/skins/build`, `…/skins/export/<skin>`, `…/skins/import`. |
| Pick sections when applying / enabling / changing | Settings → Appearance → Choose…: section checkboxes with previews, live preview; `skins.mjs use <app> <skin> --include / --exclude`; `POST …/skins/<app>/use {include, exclude}`. |
| A mix asks to create the new skin in a dialog | *Save as a new skin* dialog (name, description, auto thumbnail): Save as new / Apply without saving / Cancel. Applying a whole skin is never a mix. |

API reach for every feature (REST, MCP, CLI, voice, deep links) is the table in the PR body.
