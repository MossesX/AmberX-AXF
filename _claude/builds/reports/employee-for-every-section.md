## 3. Wiring: events in the chat as the owner

- Node: `import { crewSay } from 'framework/cli/crew-say.mjs'` → `crewSay('dispatcher', 'start', 'Started x on hulu, Opus.', { ref })`. It finds the registry by capability `service:crew-sections@1` (never by folder), runs the post in a child process (sync, ~0.2 s, only on events) and never throws.
- Shell: `node framework/cli/crew-say.mjs <section> <event> <text> --ref r || true`.
- Python plugins: capability `axf.crew-sections@1` `say(section, event, text, ref)`, returns at once (side thread, one writer at a time).
- Push banner's land folder may import only node built-ins (zero-token rule, `land.test.mjs`): it spawns the CLI itself (`land.mjs crewSay`).
- A line is a `report` from the owner with `jobId` `<section>` or `<section>:<build|PR>`: no swarm-chat contract change, Android readers show it as is.
- Chat switch respected: `core.post` drops it while the chat or that agent's voice is off. Same line once per 30 min (6 h for "still stuck" lines), so a minute-by-minute watchdog says it once.
- Events: `start`, `done`, `failed`, `blocked`, `waiting` (for Brett). Examples: "Split x by rules … Brett, check the steps", "Started x on hulu, Opus", "x stopped with steps left and is back in Pending. Brett, it needs you", "Brett, x (#512): its screenshots are waiting in UI Review", "Testing #10, #11 together", "Kicked #9 out of the queue: CI is red", "Nightly deploy failed: the installer exited 2", "Account hulu stopped (usage).
