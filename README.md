# AmberX AXF — cross-platform app framework (v0.1.0)

AmberX AXF builds apps whose entire UI is made of **hot-swappable assets**. Every theme, layout, menu, toolbar,
dialog, popup, button, slider, container and access policy is a JSON asset in one shared format (`asset@1`),
so any app built on AmberX AXF can load any other AmberX AXF app's assets.

```
amberx-axf/
├── framework/
│   ├── core/            engines + runtime (framework-agnostic TypeScript)
│   │   ├── engines/     theme · layout · components · uac · actions
│   │   ├── registry.ts  asset store        validate.ts  schema validation
│   │   └── runtime.ts   AxfRuntime: active assets, roles, overlays, hot-swap
│   ├── react/           AxfProvider, AppShell, controls, menus, overlays, studio views
│   ├── ui/axf.css     base stylesheet — reads only engine-compiled CSS variables
│   ├── assets/          39 starter assets (13 types × 3)
│   ├── schemas/         asset-types.json (single source of truth), app-structure.json, json/ (generated JSON Schemas)
│   ├── templates/react-ts/   boilerplate used by `axf init`
│   ├── cli/             build-engine.mjs (programmatic API) + axf.mjs (CLI)
│   └── defaults.json    default asset per slot, baked into every new app
└── apps/demo/           generated by `axf init` — untouched init output
```

## Engines

| Engine | Input asset(s) | Output |
| --- | --- | --- |
| Theme | `color-theme`, `style-theme` | `--fx-*` CSS variables (colors, fonts, radii, spacing, shadows, motion, blur) |
| Layout | `layout` | CSS grid areas/columns/rows for desktop + a single-column phone grid |
| Component style | `button`, `slider`, `container`, `dialog`, `popup`, `context-menu` | CSS variables + root `data-fx-*` attributes |
| User account control | `uac-policy` | role → permission resolution (inheritance, `*` and `ns.*` wildcards), hide/disable gating |
| Context menu | `context-menu` | per-target menus (`default`, `asset-card`, `nav-item`, …) with `{payload}` substitution |
| Action | menus, toolbars, shortcuts | command bus with a standard vocabulary (`file.save`, `edit.undo`, `swap:<type>:<id>` …) |

Hot-swap = `runtime.swap(type, id)` → engines recompile → variables/attributes land on `<html>`. Theme changes
don't re-render React; structural assets (menus, layout, nav) re-render only the components that read them.
Choices persist per app in `localStorage`.

## Build engine

```bash
node framework/cli/axf.mjs init apps/my-app --name "My App" --targets web,desktop,android
node framework/cli/axf.mjs validate apps/my-app      # structure, assets, defaults, baked-file hashes
node framework/cli/axf.mjs list apps/my-app
node framework/cli/axf.mjs new-asset color-theme my-theme --from amber-ember --dir apps/my-app
node framework/cli/axf.mjs validate --framework      # the framework's own assets
node framework/cli/axf.mjs schemas                   # regenerate JSON Schemas
```

`init` copies the template, **bakes** `core/`, `react/`, `ui/` and `schemas/` into `src/axf/`, copies every
starter asset into `src/assets/`, writes `axf.manifest.json` (defaults + file structure) and `axf.lock.json`
(hashes of baked files), then validates the result. Apps left on defaults look identical.

`build-engine.mjs` exports `init`, `validateApp`, `loadAssets`, `validateAsset`, `newAsset` and `writeSchemas`,
so the same engine can sit behind an HTTP API, a browser UI, an SSH session or an MCP server.

## Runtime API (`window.AXF`)

```js
AXF.swap('color-theme', 'neon-tide')   // or 'next' | 'prev' | 'random'
AXF.randomize(); AXF.reset()
AXF.importAsset(json)                  // validate + register + activate
AXF.exportAsset('layout', 'focus-top')
AXF.setRole('admin'); AXF.can('dev.deploy')
AXF.dispatch('file.save'); AXF.toast('Hi', 'success')
```

## Deploying the Dev Console (console.amberxai.com)

One command as root on the VPS builds the console + Python API + server panel container and puts it behind
Coolify's Traefik with HTTPS, then keeps it updated from `main` every 5 minutes:

```bash
curl -fsSL https://raw.githubusercontent.com/MossesX/AmberX-AXF/main/deploy/install-console.sh | bash
```

It prints the `AXF_TOKEN` the panel needs for server control and the terminal (`/panel`). Add `GITHUB_TOKEN=…`
in front for one-click CI artifact downloads (APK, Maven repo). Point an A record `console` → the VPS IP.

## Deploying the demo (axf.amberxai.com)

`.github/workflows/deploy.yml` validates and builds `apps/demo` on every push to `main` and publishes `dist/`
to the `site` branch. The VPS serves that branch with nginx and pulls it every 2 minutes, so GitHub never
holds server credentials.

One-time server setup (as root on the VPS, e.g. from Hostinger's browser terminal):

```bash
curl -fsSL https://raw.githubusercontent.com/MossesX/AmberX-AXF/main/deploy/install.sh | bash
```

It installs nginx/certbot/git if needed, clones the `site` branch into `/var/www/axf.amberxai.com`, writes an
nginx site with SPA fallback, adds the update cron job, and issues a Let's Encrypt certificate once the `xaf`
A record points at the server. It stops without changes if another web server holds port 80. Safe to re-run.

## Android port (v0.2.0)

`framework/android/` is the Kotlin + Jetpack Compose port: a pure-Kotlin kernel (`axf-kernel`), Android
adapters, Compose UI with UI-kit switching, navigation, data, network, devtools, testing, and the libraries
(`lib-settings`, `lib-logging` real; `lib-admin`, `lib-accounts`, `lib-profile`, `lib-billing` as placeholder
modules with contracts and mock providers). Templates: `react-ts` (Vite SPA), `next-ts` (Next.js 15 App Router, static export by default), `android-compose`. `apps/console-web` is the **AXF Dev Console** (React/TypeScript on the web port + a Python FastAPI API that runs the build engine; `server/Dockerfile` deploys both); `apps/console` is its Android showcase, the first app on the
port: it tracks what's built, assembles libraries from the feature catalog, generates demo apps and manages
boilerplates. See `framework/android/README.md`, `framework/spec/PORTING.md`, `framework/boilerplates/README.md`.

```bash
node framework/cli/axf.mjs init apps/my-app --template android-compose --boilerplate notes --name "My Notes"
node framework/cli/axf.mjs new-module media --label "Media" --capabilities android.media,android.camera
node framework/cli/axf.mjs new-demo media
node framework/cli/axf.mjs dev apps/console          # live-reload assets to the device
node framework/cli/axf.mjs serve --token secret      # HTTP build engine for the Dev Console (VPS)
node framework/cli/tracker.mjs                       # regenerate tracker.json from the catalog + status
```
