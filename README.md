# Frame — cross-platform app framework (v0.1.0)

Frame builds apps whose entire UI is made of **hot-swappable assets**. Every theme, layout, menu, toolbar,
dialog, popup, button, slider, container and access policy is a JSON asset in one shared format (`asset@1`),
so any app built on Frame can load any other Frame app's assets.

```
frame/
├── framework/
│   ├── core/            engines + runtime (framework-agnostic TypeScript)
│   │   ├── engines/     theme · layout · components · uac · actions
│   │   ├── registry.ts  asset store        validate.ts  schema validation
│   │   └── runtime.ts   FrameRuntime: active assets, roles, overlays, hot-swap
│   ├── react/           FrameProvider, AppShell, controls, menus, overlays, studio views
│   ├── ui/frame.css     base stylesheet — reads only engine-compiled CSS variables
│   ├── assets/          39 starter assets (13 types × 3)
│   ├── schemas/         asset-types.json (single source of truth), app-structure.json, json/ (generated JSON Schemas)
│   ├── templates/react-ts/   boilerplate used by `frame init`
│   ├── cli/             build-engine.mjs (programmatic API) + frame.mjs (CLI)
│   └── defaults.json    default asset per slot, baked into every new app
└── apps/demo/           generated by `frame init` — untouched init output
```

## Engines

| Engine | Input asset(s) | Output |
| --- | --- | --- |
| Theme | `color-theme`, `style-theme` | `--fx-*` CSS variables (colors, fonts, radii, spacing, shadows, motion, blur) |
| Layout | `layout` | CSS grid areas/columns/rows for desktop + a single-column phone grid |
| Component style | `button`, `slider`, `container`, `dialog`, `popup`, `context-menu` | CSS variables + root `data-fx-*` attributes |
| User account control | `uac-policy` | role → permission resolution (inheritance, `*` and `ns.*` wildcards), hide/disable gating |
| Context menu | `context-menu` | per-target menus (`default`, `asset-card`, `nav-item`, …) with `{payload}` substitution |
| Action | menus, toolbars, shortcuts | command bus with a standard vocabulary (`file.save`, `edit.undo`, `swap:<type>:<id>` …) |

Hot-swap = `runtime.swap(type, id)` → engines recompile → variables/attributes land on `<html>`. Theme changes
don't re-render React; structural assets (menus, layout, nav) re-render only the components that read them.
Choices persist per app in `localStorage`.

## Build engine

```bash
node framework/cli/frame.mjs init apps/my-app --name "My App" --targets web,desktop,android
node framework/cli/frame.mjs validate apps/my-app      # structure, assets, defaults, baked-file hashes
node framework/cli/frame.mjs list apps/my-app
node framework/cli/frame.mjs new-asset color-theme my-theme --from amber-ember --dir apps/my-app
node framework/cli/frame.mjs validate --framework      # the framework's own assets
node framework/cli/frame.mjs schemas                   # regenerate JSON Schemas
```

`init` copies the template, **bakes** `core/`, `react/`, `ui/` and `schemas/` into `src/frame/`, copies every
starter asset into `src/assets/`, writes `frame.manifest.json` (defaults + file structure) and `frame.lock.json`
(hashes of baked files), then validates the result. Apps left on defaults look identical.

`build-engine.mjs` exports `init`, `validateApp`, `loadAssets`, `validateAsset`, `newAsset` and `writeSchemas`,
so the same engine can sit behind an HTTP API, a browser UI, an SSH session or an MCP server.

## Runtime API (`window.Frame`)

```js
Frame.swap('color-theme', 'neon-tide')   // or 'next' | 'prev' | 'random'
Frame.randomize(); Frame.reset()
Frame.importAsset(json)                  // validate + register + activate
Frame.exportAsset('layout', 'focus-top')
Frame.setRole('admin'); Frame.can('dev.deploy')
Frame.dispatch('file.save'); Frame.toast('Hi', 'success')
```

## Deploying the demo (xaf.amberxai.com)

`.github/workflows/deploy.yml` validates and builds `apps/demo` on every push to `main`, then copies `dist/`
to the VPS over SSH. `deploy/remote-setup.sh` runs on the server first: it installs nginx/certbot if needed,
creates `/var/www/xaf.amberxai.com`, writes an nginx site with SPA fallback, and issues a Let's Encrypt
certificate once DNS points at the server. It refuses to install nginx if another web server holds port 80.

Repository secrets (Settings → Secrets and variables → Actions):

| Secret | Required | Value |
| --- | --- | --- |
| `VPS_HOST` | yes | VPS IP address |
| `VPS_SSH_KEY` or `VPS_PASSWORD` | one of them | private key (preferred) or root password |
| `VPS_USER` | no | defaults to `root` |
| `VPS_PORT` | no | defaults to `22` |
| `CERTBOT_EMAIL` | no | email for certificate expiry notices |

DNS: an `A` record for `xaf` on `amberxai.com` pointing at the VPS IP.
